# 05 · 接口清单与契约

> 面向谁：前后端联调、写新接口的同学。
> **逐条权威清单**在 `README.md` 第三章（含说明与认证要求）；本篇给的是**按域速查表 + 边界规则 + 错误码**。
> 所有路由都在网关 `duoduo-gateway/src/main/resources/application.yml` 里显式声明，**没有隐式路由**。

### 1.6 AI 导购域（`duoduo-ai:8086`，A9「多多」）
| 方法 | 路径 | 认证 |
|---|---|---|
| POST | `/api/duoduo/chat`（`{message, history[{role,content}]}` → `{reply, recommendations[], mode}`） | **免登录**（白名单） |

## 2. 认证与放行边界（最容易出错的地方）

| 层级 | 规则 |
|---|---|
| 网关白名单 | 按**路径前缀**匹配（`GatewaySecurityProperties.whitelist`）：`/api/auth/{login,register,sms/**,refresh}`、`/api/products/**`、`/api/categories/**`、`/api/home/**`、`/api/listings/**`、`/api/meta/**`、`/api/coupons/templates`（**精确路径，不是 `/api/coupons/**`**）、`/api/duoduo/{chat,capabilities}`、`/api/payments/{callback,sandbox}/**`、`/sandbox/pay/**`、`/api/reviews/product/**`、`/actuator/**` |
| 身份透传 | 网关校验令牌后注入 `X-User-Id` / `X-User-Phone` / `X-User-Role`，**并先剥离客户端伪造的同名头** |
| 内部接口 | `InternalTokenFilter`（user / product / trade / **fulfilment** / **marketing** 各一份；用户域那份 A8 扩展至 `/api/addresses/internal/**`）：路径前缀命中即校验 `X-Internal-Token`，**失败关闭** |
| 角色 | `role` ∈ `USER/SELLER/OPERATOR/ADMIN`；比较一律忽略大小写（历史 bug：`"admin".equals(role)` 在大写存储下永远 false） |

> ⚠️ **白名单按路径而非方法匹配**：所以**不要把需要登录的接口放进白名单前缀下**。
> 例如履约域只放行 `/api/reviews/product/**`；若把提交评价也挪进 `product/` 子路径，网关就不再拦未登录流量。
> 同理，**优惠券只放行精确路径 `/api/coupons/templates`** —— 若写成 `/api/coupons/**`，
> 连「领券」「我的券包」「内部锁券 / 核销 / 解锁」都会变成匿名可调（A5 的取舍，同一纪律）。

## 3. 响应与错误约定

统一结构（`duoduo-common` 的 `ApiResponse`）：
```json
{ "code": "SUCCESS", "message": "ok", "data": {...}, "requestId": "...", "timestamp": 1789700721253 }
```
分页统一 `PageResult{items,total,page,pageSize,pageCount}`（`page` 从 1 开始；各服务上限默认 100 / 列表默认 10~20）。

| `code` | HTTP | 触发场景 |
|---|---|---|
| `SUCCESS` | 200 | 成功 |
| `VALIDATION_ERROR` | 400 | 参数格式/取值不合法（注解校验、服务层参数校验） |
| `UNSUPPORTED_MEDIA_TYPE` | 415 | Content-Type 不对（**曾经落到兜底 500，已修**） |
| `UNAUTHORIZED` | 401 | 未登录/令牌过期（网关拦截） |
| `FORBIDDEN` | 403 | 无权限（非运营、非本人、内部凭据错误） |
| `NOT_FOUND` | 404 | 资源不存在 |
| `CONFLICT` | 409 | 状态冲突（重复评价、重复发货、唯一键撞键） |
| `BUSINESS_RULE` | 422 | 业务规则不满足（订单状态不允许、驳回未填原因、商品不在订单中、**购物车为空**） |
| `ORDER_STATUS_ILLEGAL` / `STOCK_INSUFFICIENT` / `PAYMENT_*` | 422 / 401 | 订单状态、库存不足、支付验签与金额核对 |
| `RATE_LIMITED` | 429 | 限流（**A9 AI 导购**：每 IP 每分钟；客户端**不应自动重试**，重试只会更早撞上限） |
| `DEGRADED` | 503 | 依赖不可用已降级（**A9**：未配置大模型 / LLM 超时；**A10** 检索不可用时是**原地走 MySQL 并返回 200**，不返回此码） |
| `INTERNAL` | 500 | 兜底（**客户端错误绝不应落到这里**，落到即缺陷） |

> **⚠️ 400 与 422 的边界（A8 实测踩过）**：下单时**收货信息缺失**是「参数本身没给」→ **400 / `VALIDATION_ERROR`**；
> 而**购物车为空**是「参数都对但业务前提不成立」→ **422 / `BUSINESS_RULE`**。
> 写断言时必须**同时检查 HTTP 状态与 `code`** —— 只查状态会出「假绿灯」（如本该验 A 却撞上 B，两者返回不同状态时看似通过）。

## 4. ID 与数值的 JSON 序列化（A8 / T-39 根治后**必知**）

`duoduo-common-web` 的 `LongToStringJacksonModule` 对**所有服务出参**统一生效：

| Java 类型 | 出参形态 |
|---|---|
| `Long` / `long` / `BigInteger`（**默认**） | **JSON 字符串**（防 18~19 位雪花 ID 被浏览器 `JSON.parse` 静默四舍五入） |
| `Long` 且**字段名命中语义白名单** | **JSON 数字**（金额 / 计数 / epoch 毫秒时间戳三类） |

- **新增 ID 类字段**：什么都不用做（默认已是字符串）；前端类型写 `string`。
- **新增数值类 `Long` 字段**：若字段名不在白名单内，**必须补进白名单**，否则前端 `"12900" / 100` → `NaN`。
- **反序列化不受影响**：入参接受 number 或 string。
- 详细白名单与反例见 `docs/agent/04` §3.1 与 `03` 篇 INV-17。

> 项目里有条被反复引用的纪律：**400 与 422 必须分清**。400 = 调用方参数写错（是 bug），
> 422 = 正常业务分支（订单没完成、商品不在订单里）。混用会让真 bug 淹没在业务分支里。

## 5. 契约产物（A6 已交付）

`scripts/export-openapi.ps1` 从各业务服务 `/v3/api-docs` 导出 **6 份 JSON**
（user / product / trade / fulfilment / marketing / **ai**）+ `endpoints.md` 端点摘要，
**合计 125 个端点**（user 26 / product 32 / trade 37 / fulfilment 19 / marketing 9 / ai 2），与 `docs/agent/04` 逐条核对一致。
网关是 WebFlux，没有 `/v3/api-docs`（knife4j 属 MVC 生态），故不导出。

> 新增 / 修改接口时**四处都要同步**：Controller 注解 → `docs/agent/04` → 本包第 05 篇 → 重跑一次导出脚本，否则交接包会立刻过期。
> **安全边界**：网关路由是显式前缀白名单，`/v3/api-docs` 与 `/doc.html` **不会**出现在公网入口。
