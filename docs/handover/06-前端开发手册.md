# 06 · 前端开发手册

> 面向谁：要改/加页面的同学。读完能得到什么：知道代码在哪、请求怎么写、五大页面域各自覆盖什么、哪些坑只在浏览器里现形。

## 1. 技术栈与启动

| 项 | 值 |
|---|---|
| 框架 | React 18 + TypeScript 5.6（`strict`）+ Vite 5 |
| 目录 | `frontend/src/{api,components,pages,store}` |
| 启动 | `cd frontend && npm install && node node_modules/vite/bin/vite.js --port 3000 --strictPort --host localhost` |
| 访问 | **`http://localhost:3000`（不能用 127.0.0.1；也不要用 5173，本机该端口在 Windows 排除段内）** |
| 校验 | `./node_modules/.bin/tsc --noEmit` 与 `./node_modules/.bin/vite build`（提交前必跑） |
| 接口指向 | 默认走网关 `:8080`（Vite dev server 代理 `/api`） |

## 2. 目录职责

| 目录 | 内容 |
|---|---|
| `src/api/client.ts` | 类型化客户端：解包 `data`、**401 单飞 refresh 并重放**、5xx 与网络错误退避重试（≤3 次）、4xx 不重试、`ApiError` 分类、`toFriendlyMessage` |
| `src/api/endpoints.ts` | 端点清单（按域分组：`userApi` / `productApi` / `cartApi` / `orderApi` / `paymentApi` / `sellerApi` / `adminApi` / `reviewApi` / `creditApi` / **`couponApi`**），文件头写明与网关路由的对应关系 |
| `src/api/types.ts` | 与 Java DTO 对齐的类型；**大整数（雪花 ID）在本项目按 number 处理有精度风险**，见 §6 |
| `src/components/ui.tsx` | 基础件：卡片/分页/弹窗（Modal）/Toast/`Stars`/状态步骤条/空态 `Empty`/`Spinner`… |
| `src/components/hooks.ts` | `useAsync(fn, enabled, deps)` —— 统一的加载/错误/重载 |
| `src/store/auth.tsx` | 登录态唯一判据是 `GET /api/users/me`（令牌在 httpOnly Cookie，前端不碰令牌） |
| `src/store/app.tsx` | 全局购物车角标等 |
| `src/pages/` | 页面，按域分子目录：根级（买家端，含 `Coupons.tsx`）/ `seller/`（商家端）/ `admin/`（平台后台）/ `reviews`（见下） |

## 3. 五大页面域

| 域 | 路由（代表） | 说明 |
|---|---|---|
| 买家端 | `/`、`/search`、`/product/:id`、`/listings`、`/cart`、`/checkout`、`/orders`、`/orders/:orderNo`、`/login`、`/pets`、`/me` | 主交易闭环 10 页；PC 端扫码支付 + 3 秒轮询 |
| 商家端 | `/seller`、`/seller/orders`、`/seller/orders/:orderNo`、`/seller/settlements`、`/seller/products`、`/seller/after-sales` | `RequireSeller` 守卫只校验**登录**，真边界在后端 403 |
| 平台后台 | `/admin`、`/admin/audits`、`/admin/categories`、`/admin/brands`、`/admin/orders`、`/admin/after-sales` | `RequireOperator`；非运营渲染 `AdminDenied` |
| 评价 | 详情页评价区（`components/ReviewSection.tsx`）、`/reviews/new?orderNo=…`、`/reviews/mine` | 已评过的商品不再出现在表单；「去评价/已评价」批量判断 |
| **优惠券（A5）** | `/coupons`（`pages/Coupons.tsx`：领券中心 + 我的券包双页签） | **刻意不套 `RequireAuth`** —— 见 §4 的取舍；一级导航「优惠券」、用户下拉与「我的」页「我的券包」三个入口 |

## 4. 写一个新页面的标准动作

1. 在 `api/types.ts` 加类型（字段名与 Java DTO **逐字对齐**，后端用 `record`，前端用 `interface`）；
2. 在 `api/endpoints.ts` 加端点函数（放在对应域的 `xxxApi` 对象里，注明认证要求）；
3. 页面用 `useAsync` 拉数据，显式处理**加载态 / 空态 / 错误态**三态（不要只写成功分支）；
4. 失败提示走 `toFriendlyMessage(err)`，4xx 不重试、5xx 自动重试由 client 统一负责；
5. 在 `App.tsx` 挂路由（需登录的包 `RequireAuth`，角色页再加 `RequireSeller`/`RequireOperator`）；
   **公开落地页可不套 `RequireAuth`** —— 取舍：领券中心 `/coupons` 是面向未登录访客的公开页
   （先让用户看得到「有什么券」，点「立即领取」时才引导登录），因此**服务端必须把未登录态也判成
   `claimable=false`**（原因「登录后可领取」），否则前端会渲染一个注定 401 的按钮。
   同理，公开页不能依赖 `RequireAuth` 提供的用户信息。
6. 入口挂到导航（`components/Layout.tsx`）或「我的」页快捷入口；
7. 跑 `tsc --noEmit` + `vite build`，再用真实浏览器走一遍（见 07 篇）。

## 6. 只在浏览器里现形的坑（务必记住）

| 坑 | 现象 | 根因与对策 |
|---|---|---|
| CORS 白名单只认 localhost | 页面显示「没有权限执行该操作」，curl 复现不出来 | 必须用 `http://localhost:3000`；换来源要同步 `CORS_ORIGINS` |
| 雪花 ID 精度 | 拿 id 去请求得到「查无此单」；写夹具写到了别的 id 上 | 19 位 > `Number.MAX_SAFE_INTEGER`，`JSON.parse` 会静默改值；确需主键时按**原始响应文本**正则提取，比较用**业务键**（订单号） |
| 依赖数组用数组/对象 | 页面每轮渲染都重发请求 | 依赖写成 `primitive`（如 `orderNos.join(',')`），数组每次都是新引用 |
| 空态与错误态混淆 | 新商品没评价却显示「加载失败」 | 空数据是正常状态，只有请求失败才是错误（见 `ReviewSection`） |
