## 2. 刻意不做的边界（不是遗漏，是当前阶段的选择）

| 边界 | 原因 | 将来怎么做 |
|---|---|---|
| **不接真实微信/支付宝** | 需商户资质（企业实名 + 备案回调域名）；用户已拍板改用**沙箱支付** | 新增 `PaymentChannel` 实现 + 配商户密钥即可，链路形态已完全仿真 |
| **不做微信小程序（M7）** | 需小程序 AppID | 复用同一套预下单/轮询接口，登录接 `code2Session` |
| **不做 AI 导购「多多」/ ES 检索 / RocketMQ 削峰 / Sentinel 限流 / 压测** | 依赖新中间件，风险与成本都高 | 按「营销 → 检索 → 削峰」顺序推进 |
| **不做物流轨迹 / 售后仲裁工单 / 信用分** | 同属 `duoduo-fulfilment` 域，等评价跑稳再扩 | 同域内扩展最省（信用分所需真实主体数据已在评价表保留） |
| **不做优惠券营销（`duoduo-marketing`）** | 需要新服务与跨域抵扣链路 | 新起模块，注意下单链路要新增「券校验 + 抵扣回滚」 |
| **后台不做退款/发货干预** | 已付款/已发货订单只走退款与售后的合法流转 | 保持：后台只强关「待付款」单 |
| **未做地址簿** | 下单时直接填收货信息 | 商品/用户域加地址 CRUD，下单取默认地址 |

## 3. 「值钱的坑」汇总（跨轮次累积，别重踩）

1. **product 服务 `id-type: input`**：实体 insert 必须显式赋雪花 id，否则 `Column 'id' cannot be null` 500。
2. **审核类接口两层命名**：对外动词 `APPROVE/REJECT` ≠ 库内状态 `APPROVED/REJECTED`，必须显式映射。
3. **后台列表不能复用只含 ACTIVE 的公开查询**，否则停用项消失、无法恢复。
4. **PowerShell 5.1 中文脚本必须 UTF-8 with BOM**；`docker exec mysql` 控制台输出是 GBK，
   **中文等值断言会假失败** → 库内只判状态/非空，中文走接口读回比对。
5. **PS 5.1 里 `$VAR?` 会被当成变量名**（`?` 是合法变量名字符），`"$SPU?page=1"` 展开成 `=1&pageSize=50`；
   带查询串一律写 `${SPU}?page=1`。
6. **19 位雪花主键经 `ConvertFrom-Json` / `JSON.parse` 都会丢精度**（PS 与 JS 同理）：
   断言用业务键（订单号）比较，确需主键时从原始响应文本正则提取。
7. **服务间只读接口要裁剪字段**（订单事实不带收货人信息、用户资料只回昵称头像），
   并按对端服务端口直连 + `X-Internal-Token`；**断言失败先确认「打的是哪个服务」**。
8. **前端必须走 `http://localhost:5173`**（CORS 白名单只认 localhost）；
   **单模块 Maven 打包必须带 `-am`**（否则依赖解析失败）；
   **腾讯文档写入长文要分块**（命令行参数约 32KB 上限）。

## 4. 接手后的推荐顺序

```
① 环境跑通（01 篇五步 → 8 容器 healthy + 9 套冒烟全绿）        ← 先证明「基线是好的」
② 补偿 I-14（历史订单托管单回补 + 自测）                        ← 唯一会污染资金台账的洞
③ 同域扩展：物流轨迹 → 售后仲裁 → 信用分（duoduo-fulfilment）    ← 复用度最高
④ 营销（duoduo-marketing）+ 前端领券中心                        ← 需要新服务与下单抵扣链路
⑤ 契约与 CI 补强（OpenAPI 导出 + CI 子集）                      ← 让后续迭代不再靠人肉
⑥ AI / ES / MQ / 压测（P3/P4）                                 ← 需要新中间件，最后做
```
