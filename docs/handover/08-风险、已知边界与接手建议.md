| ~~不做地址簿~~ **已完成（A8，2026-09-23）** | 属下单前置基础设施 | 已交付：用户域 `t_user_address` + 7 端点 + 交易域下单取**快照** + 前端地址管理页与结算选地址 |

## 3. 「值钱的坑」汇总（跨轮次累积，别重踩）

1. **product 服务 `id-type: input`**：实体 insert 必须显式赋雪花 id，否则 `Column 'id' cannot be null` 500。
2. **审核类接口两层命名**：对外动词 `APPROVE/REJECT` ≠ 库内状态 `APPROVED/REJECTED`，必须显式映射。
3. **后台列表不能复用只含 ACTIVE 的公开查询**，否则停用项消失、无法恢复。
4. **PowerShell 5.1 中文脚本必须 UTF-8 with BOM**；`docker exec mysql` 控制台输出是 GBK，
   **中文等值断言会假失败** → 库内只判状态/非空，中文走接口读回比对。
5. **PS 5.1 里 `$VAR?` 会被当成变量名**（`?` 是合法变量名字符），`"$SPU?page=1"` 展开成 `=1&pageSize=50`；
   带查询串一律写 `${SPU}?page=1`。
6. **19 位雪花主键经 `ConvertFrom-Json` / `JSON.parse` 都会丢精度**（PS 与 JS 同理）：
   断言用业务键（订单号）比较，确需主键时从原始响应文本正则提取。
7. **服务间只读接口要裁剪字段**（订单事实不带收货人信息、用户资料只回昵称头像），
   并按对端服务端口直连 + `X-Internal-Token`；**断言失败先确认「打的是哪个服务」**。
8. **前端必须走 `http://localhost:3000`**（CORS 白名单只认 `localhost`，且 5173 在本机落在 Windows 排除端口段内）；
   **单模块 Maven 打包必须带 `-am`**（否则依赖解析失败）；
   **腾讯文档写入长文要分块**（命令行参数约 32KB 上限）。
9. **改完源码必须重建并重启对应容器再跑冒烟**：`docker compose build <svc>-app` **只产出镜像、不重启容器**；
   在 build 之后才补写的代码根本不在镜像里。表现为「代码明明改了、断言还是失败、日志也看不到新分支」
   —— A5 本轮第二次踩到（`coupon-smoke.ps1` 首跑 143 通过 / 2 失败，重建后 145/145 全绿）。
   顺序固定为：`mvn package` → `build` → `up -d` → 跑冒烟（详见 `docs/agent/08` 篇 **T-37**）。
10. **本机 Node 无法创建子进程**（`spawnSync` / `execFileSync` 一律 `EBUSY errno -4082`，两版 Node、沙箱内外都一样）：
   所以**别在 `.mjs` 里用 `execFileSync('docker', …)` 跑 SQL** —— e2e 夹具的建/删交给 PowerShell
   （`& docker exec duoduo-mysql mysql …`），Node 只做 HTTP + 浏览器。参考 `scripts/e2e/coupon-ui-fixture.ps1`
   与 `coupon-ui-check.mjs` 的分工（详见 `docs/agent/08` 篇 **T-38**）。
11. **改公共模块（`duoduo-common` / `duoduo-common-web`）后必须 `mvn -DskipTests clean install`**：
    `mvn package` 是**增量**的，业务模块源码没动就**不会重打业务 fat jar**，Dockerfile `COPY` 的仍是内嵌旧
    common-web 的旧 jar → 现象是「代码对、容器里跑的不是这份代码」。另外 `docker compose up -d <svc>`
    在镜像 id 变了但容器配置没变时**不会换容器**，必须 `--force-recreate`（详见 `docs/agent/08` 篇 **T-41**）。
12. **`Long`/`long`/`BigInteger` 出参已全局默认序列化为 JSON 字符串**（A8 根治 T-39）：
    新增**数值类** `Long` 字段时，若字段名不在 `NUMERIC_LONG_FIELDS` 白名单内，**必须补进白名单** ——
    否则前端 `"12900" / 100` → `NaN` → 页面金额全变「¥NaN」。**判据是字段语义，不是 Java 类型**
    （全站 63 处金额字段都是 `Long`）。白名单集合用 `Set.copyOf(Arrays.asList(...))`，
    `Set.of()` 遇重复元素在**运行期**抛 `IllegalArgumentException`（详见 `docs/agent/08` 篇 **T-40**）。
13. **`useAsync` 的初始 `data` 是 `undefined`，不是 `null`**：判「还在加载」写 `x === undefined`，
    写 `x === null` 是**死代码**（`Checkout.tsx` 因此把有地址的用户推进手动填写模式，详见 `docs/agent/08` 篇 **T-42**）。
14. **断言不能只查 HTTP 状态码**：必须同时断言 `code`。同一状态码可能对应不同业务原因（A8 实测：
    下单缺收货信息是 400/`VALIDATION_ERROR`，购物车为空是 422/`BUSINESS_RULE`），只查状态码会出**假绿灯**。

## 4. 接手后的推荐顺序

```
① 环境跑通（01 篇五步 → 10 容器 healthy + 19 套接口冒烟 + 6 套 UI 自测全绿）  ← 先证明「基线是好的」
② I-14 已在开发库结清；若上生产，需在真实数据上跑一次回补（先 dryRun=true）   ← 唯一会污染资金台账的洞
③ 履约域（评价/售后/物流/信用分）与营销域（优惠券）、**AI 导购 A9、ES 检索 A10** 均已交付，同域内已无低成本可做项
④ 新能力：A9 联调（**待用户提供百炼 DashScope API Key**）／ A13 小程序（**待用户提供 AppID**）
⑤ 契约与 CI 补强（OpenAPI 导出 + CI 子集）                      ← 让后续迭代不再靠人肉
⑥ RocketMQ + Sentinel / XXL-Job / 压测（P3/P4）            ← 需要新中间件，最后做
```
