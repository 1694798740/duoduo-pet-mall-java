# 03 · 环境变量与密钥（脱敏）

> 面向谁：要做部署、排障、切环境的同学。
> 本篇的硬规矩：**只写变量名、用途、默认值与生产要求，绝不写任何真实密钥值**。

## 1. 变量总表（全部可在容器编排或启动参数中覆盖）

### 1.1 通用（每个服务都可能用到）

| 变量 | 用途 | 本地默认 | 生产要求 |
|---|---|---|---|
| `DUODUO_<SVC>_PORT` | 服务监听端口（`USER/PRODUCT/TRADE/FULFILMENT/MARKETING/AI/GATEWAY`） | 8081/8082/8083/8084/**8085**/**8086**/8080 | 按部署编排指定 |
| `DB_URL` | JDBC 连接串（含 `serverTimezone=UTC`） | `jdbc:mysql://127.0.0.1:3306/duoduo_<svc>?...` | 指向真实库；**不得去掉 UTC** |
| `DB_USERNAME` / `DB_PASSWORD` | 数据库账号 | `duoduo` / `duoduo` | 独立账号 + 最小权限 + 密钥托管 |
| `NACOS_ENABLED` | 是否启用服务发现 | `true` | 必须 true（网关靠 `lb://` 解析） |
| `NACOS_ADDR` | Nacos 地址 | `127.0.0.1:8848` | 集群地址 |
| `NACOS_USERNAME` / `NACOS_PASSWORD` | Nacos 账号 | `nacos` / `nacos` | 改掉默认口令 |
| `NACOS_NAMESPACE` | 命名空间 | 空 | 按环境隔离 |
| `ID_DATACENTER` / `ID_WORKER` | 雪花 ID 机房/worker | `1` 与 **1/2/3/4/5**（按服务：用户/商品/交易/履约/营销） | 多实例部署时**必须逐实例唯一**，否则会生成重复主键 |

> ⚠️ **端口变量一律用服务专属名**，例如营销域是 `DUODUO_MARKETING_PORT` 而**不是**通用名 `MARKETING_PORT`
> —— 宿主机若已存在同名通用变量，会**静默把端口改掉**，且只在容器内可见（A5 的刻意取舍，新增服务照此办理）。

### 1.2 密钥类（**五把钥匙，全部要换**）

| 变量 | 用途 | 本地默认（仅本地） | 生产要求 |
|---|---|---|---|
| `DUODUO_JWT_SECRET` | 网关签发/校验 access token 的 HMAC 密钥 | `duoduo-local-dev-secret-please-change-in-production-32b` | 长度 ≥32 字节的随机值，走密钥管理服务；**轮换会使全部登录态失效** |
| `INTERNAL_TOKEN` | 服务间内部接口凭据（`X-Internal-Token`） | `duoduo-local-dev-internal-token` | 随机长串；**各服务注入同一个值**；轮换需同时更新所有服务 |
| `SANDBOX_CALLBACK_SECRET` | 沙箱支付回调 HMAC-SHA256 验签密钥 | `duoduo-sandbox-pay-secret` | 随机值；接真实渠道时换成渠道密钥 |
| `MYSQL_ROOT_PASSWORD` | MySQL root（仅容器初始化用） | `duoduo_root` | 生产不使用 root，改用最小权限业务账号 |
| `DASHSCOPE_API_KEY`（**A9**） | 阿里云百炼（DashScope）API Key，供 `duoduo-ai` 调用大模型 | **空（默认不配）** | **待用户提供**。不配时 `duoduo-ai` 走 `mock` 形态（`DUODUO_AI_MOCK_ENABLED=true`）或对 `chat` 返回 503 `DEGRADED` —— **均为设计内行为，不是故障**；日志只记耗时与状态码，不打印 Key |

> 内部接口的**失败关闭**原则：`InternalTokenFilter` 一律「默认开启、配置为空则拒绝」，
> 绝不写「没配就放行」—— 那会把一次配置遗漏直接变成线上越权。

### 1.3 业务参数（可调，均有默认值）

| 变量 | 用途 | 默认 |
|---|---|---|
| `ORDER_EXPIRE_MINUTES` | 待付款订单超时关单（分钟） | 30 |
| `SWEEP_INTERVAL_MS` / `SWEEP_INITIAL_DELAY_MS` / `SWEEP_BATCH_SIZE` | 补偿调度周期 / 首轮延迟 / 单批上限 | 60000 / 30000 / 200 |
| `MAX_ITEMS_PER_ORDER` / `MAX_QTY_PER_SKU` | 单笔订单最多品类 / 单 SKU 最多数量 | 50 / 200 |
| `PLATFORM_FEE_BPS` | 平台佣金（基点，600 = 6%） | 600 |
| `AUTO_RECEIPT_DAYS` | 发货后自动确认收货天数（0/负=关闭） | 7 |
| `SANDBOX_CASHIER_URL` | 沙箱收银台地址（二维码指向，**必须走网关 8080**） | `http://127.0.0.1:8080/sandbox/pay` |
| `SANDBOX_EXPIRE_MINUTES` | 支付单有效期（分钟） | 15 |
| `REVIEW_MAX_CONTENT` / `REVIEW_MAX_IMAGES` / `REVIEW_APPEND_DAYS` | 评价正文上限 / 最多图片 / 追评窗口（天） | 1000 / 9 / 30 |
| `COUPON_LOCK_TTL_MINUTES` | 优惠券锁定 TTL（分钟，**必须略大于订单超时关单 30**，否则「订单还活着、券已被别人领走」） | 35 |
| `COUPON_RELEASE_SWEEP_MS` / `COUPON_RELEASE_SWEEP_DELAY_MS` / `COUPON_RELEASE_BATCH` | 券补偿调度周期 / 首轮延迟 / 单批上限 | 60000 / 30000 / 200 |
| `CORS_ORIGINS` | 网关允许的前端来源（逗号分隔） | `http://localhost:5173,http://localhost:3000` |

> **CORS 白名单是硬约束**：新增前端来源（例如换机器、换端口、内网 IP）必须加进 `CORS_ORIGINS`，
> 否则浏览器请求会被网关按非法跨域 403，表现为页面「没有权限执行该操作」。

### 1.4 A9 AI 导购 与 A10 ES 检索（第十七轮新增）

| 变量 | 含义 | 默认 | 说明 |
|---|---|---|---|
| `DUODUO_AI_BASE_URL` | DashScope OpenAI 兼容端点 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 换网关/代理时改 |
| `DUODUO_AI_MODEL` | 模型名 | `qwen-plus` | 换模型只改这里 |
| `DUODUO_AI_MOCK_ENABLED` | **mock 形态开关** | `true`（本地/CI） | 开启时不调 LLM，用确定性规则把**真实召回候选**组织成回复（整链可跑）。**生产必须置 false** —— mock 的回复不是模型生成的 |
| `DUODUO_AI_TIMEOUT_SECONDS` | 调模型的超时 | `15` | 超时 → `chat` 返回 **503 `DEGRADED`**（不让请求挂死） |
| `DUODUO_AI_RATE_LIMIT` | 每 IP 每分钟限流上限 | `20` | 超限 → **429 `RATE_LIMITED`**（客户端**不应自动重试**） |
| `DUODUO_SEARCH_ENABLED` | **是否启用 ES 检索** | `false`（product 的 `application.yml`）/ `true`（compose） | 关闭时**完全走 MySQL**，行为与接入前一致 —— 这是可回退的开关 |
| `DUODUO_ES_URL` | ES 地址 | `http://127.0.0.1:9200` | compose 网络内为 `http://duoduo-es:9200` |
| `DUODUO_SEARCH_SWEEP_MS` | 增量扫描周期（毫秒） | `15000` | **决定「库存/上下架变化多久反映到检索」**；同时也是补偿扫描周期 |
| `DUODUO_SEARCH_SYNONYMS` | 同义词分组，`;` 分组、`,` 组内 | `犬,狗;幼犬,小狗;猫咪,喵星人;仓鼠,金丝熊` | **同组各项不要共享单字**（逐字分词下共享单字本来就互相命中，写成同义词没有增量）。由**应用侧**替换，不挂 ES 分析器（见 `docs/agent/08` T-49） |

> **ES 是可选的**：`docker compose up -d` 默认**不起** `duoduo-es`（挂 `profiles: ["search"]`），
> 需要时 `docker compose --profile search up -d duoduo-es`。ES 停服时检索**原地降级 MySQL 并返回 200**，
> 页面不会挂；`management.health.elasticsearch.enabled=false` 是刻意的 —— 否则 ES 停会让 product 容器 unhealthy，
> **健康门会把降级链路本身杀掉**。

## 2. 密钥的取用与轮换建议

| 动作 | 建议 |
|---|---|
| 存放 | 一律环境变量 / 密钥管理，**不入库、不写文档、不进 Git** |
| `.env` | 只提交 `.env.example`（占位值）；真实 `.env` 在 `.gitignore` 内 |
| 轮换 JWT | 影响：所有用户需重新登录；建议灰度（新旧密钥并行校验） |
| 轮换内部凭据 | 影响：轮换瞬间跨服务调用会 403；建议先双写（两个值都接受）再停旧值 |
| 轮换 DB 口令 | 影响：连接池需重启；建议先建新账号→切配置→观察→停旧账号 |
| 审计 | 抽检日志：结构化 JSON 日志**禁止**出现口令、令牌、密钥、收货人隐私 |
