# 04 · 数据库与表结构

> 面向谁：写 SQL、加字段、做对账/排障的同学。
> 权威来源：`docs/sql/00~06*.sql`（容器初始化用，与各模块 `src/main/resources/db/schema.sql` 同源，改结构请改模块内 schema 再重新生成）。

## 1. 五库划分

| 库 | 归属服务 | 初始化脚本 | 说明 |
|---|---|---|---|
| `duoduo_user` | `duoduo-user` | `docs/sql/01-duoduo-user.sql` | 用户、令牌、宠物档案、**收货地址簿（A8）**、**运营审计日志（A7）** |
| `duoduo_product` | `duoduo-product` | `docs/sql/02-duoduo-product.sql` | 类目 / 品牌 / SPU / SKU / 库存 / 闲置 + **种子数据** |
| `duoduo_trade` | `duoduo-trade` | `docs/sql/03-duoduo-trade.sql` | 购物车 / 订单 / 明细 / 状态日志 / 冻结台账 / 支付 / 托管 |
| `duoduo_fulfilment` | `duoduo-fulfilment` | `docs/sql/04-duoduo-fulfilment.sql` | 评价与晒单 / 售后仲裁 / 物流轨迹 |
| `duoduo_marketing` | `duoduo-marketing` | `docs/sql/05-duoduo-marketing.sql` | **优惠券（A5）**：券模板 + 用户券 + 种子模板 |
| （`duoduo_trade` 增量） | `duoduo-trade` | `docs/sql/incremental/06-a5-coupon-columns.sql` | **A5 交易域增量列**：`t_order.coupon_code`（MySQL 不支持 `ADD COLUMN IF NOT EXISTS`，**重复执行报 1060 属预期**） |
| （`duoduo_user` 增量） | `duoduo-user` | `docs/sql/incremental/07-a8-user-address.sql` | **A8 收货地址簿**：`t_user_address` 建表（可独立重放） |
| （`duoduo_user` 增量） | `duoduo-user` | `docs/sql/incremental/08-a13-wechat-bind.sql` | **A13 微信绑定**：`t_user.wx_openid` + 唯一键 `uk_user_wxopenid`（重复执行报 1060 属预期） |
| （`duoduo_user` 增量） | `duoduo-user` | `docs/sql/incremental/09-a7-audit-log.sql` | **A7 运营审计日志**：`t_audit_log` 建表（`IF NOT EXISTS` 幂等，可独立重放） |
| （`nacos`） | Nacos | `00-init-databases-and-user.sql` | 中间件自用，业务账号无权限 |

**为什么分库而不是分表**：服务边界即数据边界；跨库查询一律通过服务接口（只读、凭据保护），
不允许跨库 JOIN —— 否则服务拆分就只剩「进程拆开了，库还连在一起」。

## 2. 表清单

### 2.1 `duoduo_user`
| 表 | 关键字段 | 说明 |
|---|---|---|
| `t_user` | `id`(雪花)、`phone`(唯一)、`password_hash`、`nickname`、`avatar`、`status`、`role`、`real_name`、`id_card_masked`、`credit_score`、`wx_openid`(A13, 唯一)、`last_login_at` | `role` ∈ `USER / SELLER / OPERATOR / ADMIN`；**提权已可走 A7 运营接口**（仅 ADMIN，写审计） |
| **`t_audit_log`**（A7 新增） | `id`(雪花)、`actor_id`、`actor_phone`、`action`、`target_id`、`detail`、`created_at` | **只追加、不更新、不删除**（无 updated_at）：审计价值在不可篡改的顺序历史。当前 `action=USER_ROLE_CHANGE`，`detail` 存 `old -> new`。索引按 actor / target 双向可查 |
| `t_refresh_token` | `jti`、`user_id`、`token_hash`(SHA-256)、`expires_at`、`revoked` | 刷新令牌**只存哈希**并轮转；登出即 revoke |
| `t_pet_profile` | `user_id`、`name`、`species`、`birthday`、`life_stage`、`weight`、`is_default` | 生命阶段须与生日推算一致（否则 422） |
| **`t_user_address`**（A8 新增） | `id`(雪花)、`user_id`、`receiver_name`、`receiver_phone`、`province`、`city`、`district`、`detail`、`is_default`、`deleted`、时间戳 | 收货地址簿。**默认地址唯一性不用唯一索引**（与「先取消旧默认再置新默认」的两步写有时序冲突），改在服务层**事务内**保证「至多一条默认、且不为零」；删除默认地址时**顺延**最早一条。逻辑删除（`deleted`），历史订单走快照不受影响 |

## 3. 状态枚举字典（排障必查）

| 域 | 枚举 | 取值 |
|---|---|---|
| 订单 `t_order.status` | 8 态 | `PENDING_PAYMENT` 待付款 → `PAID` 已付款 → `SHIPPED` 已发货 → `COMPLETED` 已完成；分支终态 `CLOSED` 已关闭、`REFUNDED` 已退款、`CANCELLED`(取消) |
| 支付单 `t_payment.status` | 4 态 | `PENDING` / `SUCCESS` / `EXPIRED`（超时作废）/ `CLOSED`（订单关单作废） |
| 托管 `t_settlement.status` | 3 态 | `CUSTODY` 托管中 / `RELEASED` 已放款给卖家 / `REFUNDED` 已退回买家 |
| 冻结 `t_stock_freeze.status` | — | `FROZEN` / `RELEASED` / `DEDUCTED`（付款后转实扣）/ `RESTOCK_PENDING → RESTOCKED`（退货入库补偿） |
| 审核 `t_listing.audit_status` | 3 态 | `PENDING` / `APPROVED` / `REJECTED`（**对外动词是 APPROVE/REJECT，库内是 APPROVED/REJECTED，两层别混**） |
| 评价 `t_review.audit_status` | 3 态 | 当前默认 `APPROVED`（运营审核工作台接入后改 `PENDING` 起） |
| 商品/类目/品牌 `status` | 2 态 | `ACTIVE` / `INACTIVE`（**公开接口只暴露 ACTIVE，后台列表含停用项**） |
| 券状态 `t_coupon.status` | 4 态 | `UNUSED` 未使用 → `LOCKED` 已锁定 → `USED` 已使用（终态）；`EXPIRED` 已过期（终态）；**`LOCKED` 可 `release` 回 `UNUSED`** |
| 券类型 `t_coupon_template.type` | — | `FULL_REDUCE` 满减（**v1 只实现这一种**；传其他值 422，不静默按满减处理） |

## 4. 口径约定（跨表统一，改动需评审）

| 口径 | 约定 |
|---|---|
| 金额 | 一律 `BIGINT`，单位**分**（避免浮点；前端负责展示为元） |
| 时间 | 一律 `TIMESTAMP` 且 **UTC**（容器 `TZ=UTC` + `--default-time-zone=+00:00` + JDBC `serverTimezone=UTC` 三处同口径） |
| 主键 | 一律雪花 ID `BIGINT`，**不用自增**（便于后续分库分表）；product 服务 `id-type: input`，**实体 insert 必须显式赋值** |
| 幂等 | 靠唯一索引兜底，不依赖分布式锁 |
| 状态字段 | 用 `VARCHAR` 存枚举名（可读、便于排查），不用数字码 |
| 中文写入 | 初始化脚本必须显式 `SET NAMES utf8mb4`，否则中文双重编码（历史缺陷 I-08） |

## 5. 初始化与数据说明

```bash
# 从零重建（会清空数据，仅开发环境）
docker compose down -v && docker compose up -d     # 数据卷清空后 00~06 脚本按序执行（含 05 建营销库、06 交易域增量列）
# 只补建履约库（已有数据卷时 initdb 不会重跑）
docker exec -i duoduo-mysql mysql -uroot -p<root密码> --default-character-set=utf8mb4 < docs/sql/04-duoduo-fulfilment.sql
# 只补建营销库 + 交易域券列（已有数据卷时）
docker exec -i duoduo-mysql mysql -uroot -p<root密码> --default-character-set=utf8mb4 < docs/sql/05-duoduo-marketing.sql
docker exec -i duoduo-mysql mysql -uroot -p<root密码> --default-character-set=utf8mb4 < docs/sql/incremental/06-a5-coupon-columns.sql
#   ↑ 06 重复执行会报 1060（Duplicate column name），属预期
```

- **种子数据**：商品域（类目/品牌/SPU/SKU）预置，SKU `2001`、`2002` 是自测脚本常用夹具；
  营销域预置券模板 **5001 / 5002**；用户与订单由接口产生。
- **`I-14` 历史订单缺托管单**：**已解决（A1，2026-09-18）** —— 提供幂等回补接口
  `POST /api/admin/settlements/backfill?dryRun=`，开发库缺口已清零；**生产上线时仍需在真实数据上跑一次**（先 `dryRun=true` 核对计划）。
