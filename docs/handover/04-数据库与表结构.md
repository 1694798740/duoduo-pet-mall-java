# 04 · 数据库与表结构

> 面向谁：写 SQL、加字段、做对账/排障的同学。
> 权威来源：`docs/sql/00~04*.sql`（容器初始化用，与各模块 `src/main/resources/db/schema.sql` 同源，改结构请改模块内 schema 再重新生成）。

## 1. 四库划分

| 库 | 归属服务 | 初始化脚本 | 说明 |
|---|---|---|---|
| `duoduo_user` | `duoduo-user` | `docs/sql/01-duoduo-user.sql` | 用户、令牌、宠物档案 |
| `duoduo_product` | `duoduo-product` | `docs/sql/02-duoduo-product.sql` | 类目 / 品牌 / SPU / SKU / 库存 / 闲置 + **种子数据** |
| `duoduo_trade` | `duoduo-trade` | `docs/sql/03-duoduo-trade.sql` | 购物车 / 订单 / 明细 / 状态日志 / 冻结台账 / 支付 / 托管 |
| `duoduo_fulfilment` | `duoduo-fulfilment` | `docs/sql/04-duoduo-fulfilment.sql` | 评价与晒单 |
| （`nacos`） | Nacos | `00-init-databases-and-user.sql` | 中间件自用，业务账号无权限 |

**为什么分库而不是分表**：服务边界即数据边界；跨库查询一律通过服务接口（只读、凭据保护），
不允许跨库 JOIN —— 否则服务拆分就只剩「进程拆开了，库还连在一起」。

## 2. 表清单

### 2.1 `duoduo_user`
| 表 | 关键字段 | 说明 |
|---|---|---|
| `t_user` | `id`(雪花)、`phone`(唯一)、`password_hash`、`nickname`、`avatar`、`status`、`role`、`real_name`、`id_card_masked`、`credit_score`、`last_login_at` | `role` ∈ `USER / SELLER / OPERATOR / ADMIN`；**提权目前靠手工改库** |
| `t_refresh_token` | `jti`、`user_id`、`token_hash`(SHA-256)、`expires_at`、`revoked` | 刷新令牌**只存哈希**并轮转；登出即 revoke |
| `t_pet_profile` | `user_id`、`name`、`species`、`birthday`、`life_stage`、`weight`、`is_default` | 生命阶段须与生日推算一致（否则 422） |

### 2.2 `duoduo_product`
| 表 | 关键字段 | 说明 |
|---|---|---|
| `t_category` | `id`、`parent_id`、`name`、`depth`、`sort_no`、`icon`、`status` | 两级类目；后台列表**含停用项** |
| `t_brand` | `id`、`name`、`logo`、`country`、`story`、`status` | 同上 |
| `t_spu` | `id`、`title`、`category_id`、`brand_id`、`species`、`life_stage`、`status`、`min_price`/`max_price` | 检索 6 种排序；SPU 汇总价格由 SKU 派生 |
| `t_sku` | `id`、`spu_id`、`price`、`stock`、**`frozen_stock`**、`spec_text`、`status` | **可售 = `stock - frozen_stock`**；冻结/释放/扣减走原子条件更新 |
| `t_listing` | `id`、`seller_id`、`title`、`price`、`condition_level`、`status`、`audit_status`、**`audit_reason`**、**`audit_at`** | 闲置（C2C）；对外只暴露 `status=ON_SALE 且 audit_status=APPROVED` |
| `t_spu_suitability` 等 | — | 适用属性（过敏原等），详见 02 脚本 |

### 2.3 `duoduo_trade`

| `t_order` | `id`、`order_no`(业务键)、`user_id`、`seller_id`、`order_type`、`status`、`total_amount`、`freight_amount`、`discount_amount`、`pay_amount`、收货人三字段、`logistics_company`、`logistics_no`、`close_reason`、各时间戳 | **唯一索引 `uk_order_user_idem`(user_id, idempotent_key)** 兜住重复下单 |
| `t_order_item` | `order_id`、`sku_id`、`spu_id`、`title`、`spec_text`、`main_image`、`price`、`quantity`、`amount` | **下单时刻快照**：商品改名改价不影响历史订单 |
| `t_order_status_log` | `order_id`、`from_status`、`to_status`、`operator_type`、`operator_id`、`reason` | 状态迁移全留痕（`OPERATOR` 表示运营干预） |

### 2.4 `duoduo_fulfilment`
| 表 | 关键字段 | 说明 |
|---|---|---|
| `t_review` | `id`、`order_id`、`order_no`、`user_id`、`seller_id`、`spu_id`、`sku_id`、`product_title`、`product_image`、`rating`(1-5)、`content`、`images`(JSON 数组串)、`anonymous`、`append_content`、`append_at`、`audit_status`、时间戳 | **唯一索引 `uk_review_order_user_spu`(order_id,user_id,spu_id)** = 一单一商品一评；`order_id` 由订单号派生稳定哈希 |

## 3. 状态枚举字典（排障必查）

| 域 | 枚举 | 取值 |
|---|---|---|
| 订单 `t_order.status` | 8 态 | `PENDING_PAYMENT` 待付款 → `PAID` 已付款 → `SHIPPED` 已发货 → `COMPLETED` 已完成；分支终态 `CLOSED` 已关闭、`REFUNDED` 已退款、`CANCELLED`(取消) |
| 支付单 `t_payment.status` | 4 态 | `PENDING` / `SUCCESS` / `EXPIRED`（超时作废）/ `CLOSED`（订单关单作废） |
| 托管 `t_settlement.status` | 3 态 | `CUSTODY` 托管中 / `RELEASED` 已放款给卖家 / `REFUNDED` 已退回买家 |
| 冻结 `t_stock_freeze.status` | — | `FROZEN` / `RELEASED` / `DEDUCTED`（付款后转实扣）/ `RESTOCK_PENDING → RESTOCKED`（退货入库补偿） |
| 审核 `t_listing.audit_status` | 3 态 | `PENDING` / `APPROVED` / `REJECTED`（**对外动词是 APPROVE/REJECT，库内是 APPROVED/REJECTED，两层别混**） |
| 评价 `t_review.audit_status` | 3 态 | 当前默认 `APPROVED`（运营审核工作台接入后改 `PENDING` 起） |
| 商品/类目/品牌 `status` | 2 态 | `ACTIVE` / `INACTIVE`（**公开接口只暴露 ACTIVE，后台列表含停用项**） |

## 4. 口径约定（跨表统一，改动需评审）

| 口径 | 约定 |
|---|---|
| 金额 | 一律 `BIGINT`，单位**分**（避免浮点；前端负责展示为元） |
| 时间 | 一律 `TIMESTAMP` 且 **UTC**（容器 `TZ=UTC` + `--default-time-zone=+00:00` + JDBC `serverTimezone=UTC` 三处同口径） |
| 主键 | 一律雪花 ID `BIGINT`，**不用自增**（便于后续分库分表）；product 服务 `id-type: input`，**实体 insert 必须显式赋值** |
| 幂等 | 靠唯一索引兜底，不依赖分布式锁 |
| 状态字段 | 用 `VARCHAR` 存枚举名（可读、便于排查），不用数字码 |
| 中文写入 | 初始化脚本必须显式 `SET NAMES utf8mb4`，否则中文双重编码（历史缺陷 I-08） |

## 5. 初始化与数据说明

```bash
# 从零重建（会清空数据，仅开发环境）
docker compose down -v && docker compose up -d     # 数据卷清空后 00~04 脚本按序执行
# 只补建履约库（已有数据卷时 initdb 不会重跑）
docker exec -i duoduo-mysql mysql -uroot -p<root密码> --default-character-set=utf8mb4 < docs/sql/04-duoduo-fulfilment.sql
```

- **种子数据**：仅商品域（类目/品牌/SPU/SKU）预置，SKU `2001`、`2002` 是自测脚本常用夹具；用户与订单由接口产生。
- **历史遗留（I-14，最高优先待办）**：M5-8 担保交易上线前的订单**没有 `t_settlement` 记录**，
  这些单确认收货时放款会找不到托管单（只记 ERROR，不影响买家收货）。
  开发库可清空重建，**生产上线前必须写一次性回补脚本按订单状态推断资金状态**。
