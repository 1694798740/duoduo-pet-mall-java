# 01 · 快速上手与环境搭建

> 面向谁：第一次在这台机器（或新机器）上跑起本项目的开发/测试同学。
> 读完能得到什么：从零到「9 容器全 healthy + 前端能下单 + 14 套接口冒烟 + 5 套浏览器自测全绿」的完整步骤，以及 5 个必然会踩的环境坑。

## 1. 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows（本项目开发环境为 Windows 11 + Git Bash） | 脚本为 PowerShell 5.1 与 Node 混用 |
| Docker Desktop | 必备，且**需人工启动** | 引擎是独立进程；Windows 家庭版依赖 WSL2。**当前自动化环境无法代启动**（启动需调 `wsl.exe`，在沙箱黑名单内） |
| JDK | **21** | `pom.xml` 的 `java.version=21` |
| Maven | 3.9.x（本项目自带 `maven/settings.xml`） | 全局 settings 指向已失效私服，必须用项目内配置 |
| Node | 22.x（前端）+ 可选 24.x | 前端构建与 UI 自测 |
| PowerShell | 5.1（Windows 自带） | 所有 `scripts/*.ps1` 按 5.1 编写 |

## 2. 五步跑起来

### 步骤 1 · 确认 Docker 引擎
```bash
docker info | head -5     # 必须能看到 Server 版本；看不到就是引擎没起，先手动打开 Docker Desktop
```

### 步骤 2 · 拉起容器（9 个）
```bash
cd D:\智能体项目\duoduo-pet-mall-java
docker compose up -d
docker compose ps         # 期望：mysql / redis / nacos / user / product / trade / fulfilment / marketing / gateway 全 healthy
```
| 容器 | 端口 | 职责 |
|---|---|---|
| `duoduo-mysql` | 3306 | MySQL 8.0.36，五库：`duoduo_user` / `duoduo_product` / `duoduo_trade` / `duoduo_fulfilment` / `duoduo_marketing` |
| `duoduo-redis` | 6379 | 缓存 |
| `duoduo-nacos` | 8848 | 服务发现（网关 + 5 个业务服务，共 6 个注册） |
| `duoduo-app-user` | 8081 | 用户域 |
| `duoduo-app-product` | 8082 | 商品域（含库存主数据） |
| `duoduo-app-trade` | 8083 | 交易域（订单/支付/托管/卖家中心） |
| `duoduo-app-fulfilment` | 8084 | 履约域（评价与晒单 / 售后仲裁 / 物流轨迹 / 信用分） |
| `duoduo-app-marketing` | 8085 | 营销域（优惠券：领券中心 / 券包 / 锁·解·核销 / 补偿调度） |
| `duoduo-app-gateway` | 8080 | **唯一对外入口**（鉴权、路由、CORS） |

### 步骤 3 · 构建后端（**本项目专用姿势**，别用裸 `mvn`）
两个环境坑决定了命令长这样：
```bash
# 坑 A：全局 settings.xml 的 mirrorOf=* 指向已失效的私服 100.wunding.com:1443
#        → 用项目内 maven/settings.xml 绕开（不需要改任何全局配置）
# 坑 B：沙箱/受限环境禁止 cmd.exe，mvn.cmd 起不来
#        → 用 java 直接驱动 Maven launcher
java -classpath "D:/devsoft/apache-maven-3.9.4/boot/plexus-classworlds-2.7.0.jar" \
     "-Dclassworlds.conf=D:/devsoft/apache-maven-3.9.4/bin/m2.conf" \
     "-Dmaven.home=D:/devsoft/apache-maven-3.9.4" \
     "-Dmaven.multiModuleProjectDirectory=D:/智能体项目/duoduo-pet-mall-java" \
     "-Dmaven.legacyLocalRepo=true" \
     org.codehaus.plexus.classworlds.launcher.Launcher -ntp -DskipTests package
```
> ⚠️ **只构建单个模块时必须带 `-am`**：`-pl duoduo-fulfilment package` 会因本地仓库没有
> `duoduo-common` / `duoduo-common-web` 的 jar 而 BUILD FAILURE；正确写法 `-pl duoduo-fulfilment -am package`。
> 这个坑本轮实测踩过一次（表现为「依赖解析失败」而不是编译错误）。

构建产物：`<模块>/target/<模块>-1.0.0.jar` → 由根目录 `Dockerfile`（`temurin:21-jre-alpine`、非 root 运行）打进镜像：
```bash
docker compose build duoduo-fulfilment-app
docker compose up -d duoduo-fulfilment-app      # 约 15s 后 healthy
```

### 步骤 4 · 起前端
```bash
cd frontend
npm install
node node_modules/vite/bin/vite.js --port 3000 --strictPort --host localhost
# 打开 http://localhost:3000
```
> ⚠️ **端口用 3000，不是 5173**：本机 5173 落在 Windows **排除端口段**内（Docker Desktop 启动后 WinNAT 保留
> `5149-5248` 等段，`listen` 一律 `EACCES`，不是被占用、也不是沙箱拦的）。查：`netsh int ipv4 show excludedportrange protocol=tcp`。
> `3000` 已在网关 `CORS_ORIGINS` 默认白名单里，**不用改任何配置**。
> ⚠️ **必须用 `localhost`，不能用 `127.0.0.1`**：带 `127.0.0.1` 的 Origin 不在 CORS 白名单，会被 Spring 直接 403，
> 页面只显示「没有权限执行该操作」，而 curl 不带 Origin 头复现不出来 —— 这是「只在浏览器里现形」的坑。

## 3. 常见故障与对策

| 现象 | 根因 | 对策 |
|---|---|---|
| `docker info` 无 Server 版本 | Docker Desktop 未启动 | 手动启动（自动化环境无法代启） |
| Maven 报「无法解析依赖 xxx in aliyunmaven」 | 用了全局 settings 或漏了 `-am` | 用项目 `maven/settings.xml`；单模块务必带 `-am` |
| 容器启动后服务 502/503 | 服务尚未注册到 Nacos 或健康检查未过 | `docker logs duoduo-app-<服务>`；等 15~30s |
| 前端页面「没有权限执行该操作」 | 用了 `127.0.0.1:3000` | 改用 `localhost:3000` |
| 前端 dev server 起不来：`listen EACCES ...:5173` | 5173 落在 Windows **排除端口段**（Docker Desktop 的 WinNAT 保留段） | 改用 `--port 3000` + `UI_BASE=http://localhost:3000`（3000 在 CORS 默认白名单内）。查：`netsh int ipv4 show excludedportrange protocol=tcp` |
| 改了源码、重建镜像后冒烟仍失败，且日志看不到新分支 | 只 `docker compose build` 而**没重启容器**（或在 build 之后才补的代码） | 顺序：`mvn package` → `docker compose build <svc>-app` → `docker compose up -d <svc>-app` → 再跑冒烟 |
| ps1 脚本一跑就语法报错、中文乱码 | 脚本未存成 **UTF-8 with BOM** | 用支持 BOM 的编辑器重存（PS 5.1 否则按 GBK 解析） |
| 中文断言「库里明明有、断言说没有」 | `docker exec mysql` 控制台是 GBK | 库内只判状态/非空，**中文内容走接口读回比对** |
| 断言说数据不存在，其实数据在库里 | 19 位雪花 ID 经 `ConvertFrom-Json`/`JSON.parse` 丢精度 | 断言用**业务键**（订单号），确需主键时从**原始响应文本**正则提取 |
| 请求带查询串的服务端收到怪值 | PowerShell 把 `$VAR?page=1` 整体当变量名（`?` 是合法变量名字符） | 一律写 `${VAR}?page=1` |

## 4. 降级路径（不开 Docker）

中间件可用免安装版：`scripts/start-infra.ps1`（起 MySQL/Redis）、`scripts/start-local.ps1 -Mysql`（起三进程）。
这是**备用路径**，功能对齐但未经完整验证；推荐始终走 Docker Compose。
