# 阿里云服务器部署方案（2026-10-13 搁置版）

> **状态：已搁置**。搁置原因：当前实例 2 核 4G 内存不足以承载本项目全栈（网关 + 多个 Java 微服务 + MySQL + Redis + RocketMQ + Elasticsearch）。
> **恢复条件：换到内存 ≥ 8G 的服务器后，直接按本方案第 4 节流程执行，无需重新评估。**

## 1. 已核实的实例信息（2026-10-13 截图）

| 项 | 值 | 评估 |
|----|----|------|
| 实例 | 阿里云 ECS `duoduo`（华南3 广州B） | — |
| 规格 | 2 vCPU / 4 GiB（ecs-c1m2.large，按量付费） | **内存不足**，是搁置主因 |
| 操作系统 | CentOS 7.9 64 位 | **已 EOL**（2024-06 官方停止维护），恢复部署时建议换 Ubuntu 22.04 或 Alibaba Cloud Linux 3（换镜像会清掉已装宝塔/QoderCLI） |
| 公网 | **无公网 IP**（仅私网 172.21.180.18） | 恢复时先绑定 EIP（按量付费实例不自带公网 IP） |

## 2. 目标架构

```
本机 Windows（构建 Docker 镜像）
   └─ docker push → 阿里云 ACR 个人版（免费）
                      └─ 服务器 docker pull → Docker Compose 全栈：
                          nginx :443（入口/证书） → 网关 :8080 → Java 微服务×N
                          + MySQL / Redis / RocketMQ / ES（均不对公网暴露）
用户（浏览器 / 微信小程序）──HTTPS 域名 443──→ nginx
```

**为什么镜像在本机构建**：2C4G 上现场跑 Maven 编译 + 前端 monorepo 构建会非常痛苦且可能 OOM；本机已验证的构建链直接复用。

## 3. 前置条件清单

- **系统**：Linux + Docker + Docker Compose + 4G swap；`vm.max_map_count≥262144`（ES 要求）
- **安全组/防火墙**：只开 **22 / 80 / 443**；8080、8090、8091、3306、6379、9200、RocketMQ 端口一律不对公网暴露
- **HTTPS 证书 + 已备案域名**：大陆服务器用域名提供 Web 服务必须 ICP 备案；小程序合法请求域名硬性要求 HTTPS+备案。无域名前只能 IP 直访网页端
- **凭据**：COS 密钥、生产数据库密码等以 `.env` 注入，**不复用**开发库密码

## 4. 恢复部署时的执行流程（9 步）

1. 启动实例 → 申请并绑定 EIP
2. 换操作系统 → Ubuntu 22.04（或 Alibaba Cloud Linux 3）
3. 安全组放行 22/80/443
4. 装 Docker + Compose，系统调优（swap、内核参数）
5. 本机构建全部镜像 → 推 ACR → 服务器拉取
6. 写生产 `.env`（COS 密钥、数据库密码、`STORAGE_TYPE=cos` 等）
7. 数据初始化：用 S4 备份链导入六库 + 上传卷（顺带演练备份恢复）
8. 前置 nginx：443 + 证书 + 反代网关与三个前端站点
9. 服务器侧跑一轮轻量冒烟 → 用户真机验收

## 5. 内存预算（8G 机器的参考分配）

| 组件 | 预算 |
|------|------|
| MySQL | 1.5G |
| Elasticsearch | 1G（堆 512m~1g） |
| RocketMQ broker | 1G |
| Redis | 256m |
| Java 微服务 ×N（每个限堆） | 合计 2.5~3G |
| 系统 + nginx + 余量 | 1~1.5G |

2C4G 若强行跑：全部 JVM 限堆 256~384m、ES 堆 512m、4G swap，可启动但性能打折——不建议。
