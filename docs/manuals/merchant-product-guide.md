# 商家商品管理操作手册（K-03）

> 适用站点：商家工作台 `http://merchant.localhost:8091`（生产环境以实际域名为准）
> 适用角色：店主（SELLER）、店员（STAFF，按店主配置的权限）
> 对应实现：商品域 A-01~A-17、F-04；交易域 D-05；评价域 A-16；客服域 C-04/C-05
> 最后更新：2026-10-26

---

## 0. 开始之前

| 事项 | 说明 |
|---|---|
| 账号 | 商家工作台与商城共用同一手机号账号；商家端是独立站点，登录态与商城互不影响 |
| 入驻 | 首次使用需完成实名与入驻申请，审核通过后店铺为「营业中」才能上架商品 |
| 店员 | 店主在「店员管理」邀请已注册手机号；每个店员可单独配置操作权限（F-04） |
| 权限 | 店主恒为全部权限；店员可被配置为：商品内容编辑 / 改价改库存 / 上下架删除 / 订单发货 / 售后退款 / 客服回复；全部不勾 = 仅查看 |
| 资金 | 店员默认不可查看结算与提现，钱只对店主可见 |

> 遇到 403：先看当前账号是否具备对应操作权限（店主可在「店员管理 → 权限」调整，立即生效）。
> 遇到 404：通常是商品不属于当前店铺，或商品已进入回收站。

## 1. 商品发布

### 1.1 入口与必填项

1. 进入「商品管理」→ 点击「发布商品」。
2. 必填：商品标题、类目、品牌、主图、至少一个规格（SKU）的价格与库存。
3. 选填但建议填写：副标题、商品介绍、富文本详情、详情图、规格参数、包装信息。

类目决定「类目属性模板」：模板里标记为必填的属性必须填写，否则服务端拒绝发布。
属性值最终保存在商品的 `spec_params` 中，编辑时按当前类目模板校验。

### 1.2 图片要求

- 主图会作为详情页首图；图集第一张与主图必须一致（服务端会归一，端侧也有兜底）。
- 富文本详情会经过服务端消毒（去除脚本、危险标签），只保留安全内容。
- 建议主图使用正方形、白底或场景图；详情图与主图分开维护。

### 1.3 发布后的审核

- 第三方商家商品提交后先走规则校验；未命中风险的自动通过（审核来源 `AUTO`），
  命中风险（价格异常、违禁词、内容风险等）进入「待审核」，由平台运营人工审核。
- 审核通过自动上架；驳回会写明原因并置为下架，可修改后重新提交。
- **已通过审核的商品再次编辑内容（标题 / 图片 / 详情 / 类目 / 规格结构）会回到待审核**：
  审核结论只针对「当时那段内容」。
- **只改价格 / 库存不会重新审核**（见下一节）。
- 审核中的商品不能重复提交；已通过的商品不需要「重新提审」，直接编辑即可。

### 1.4 审核状态与处理

| 状态 | 含义 | 你要做什么 |
|---|---|---|
| 待审核 | 已提交，等待平台处理 | 等待；不要重复提交 |
| 已通过 | 可正常售卖 | 无需操作；改内容会重新进入待审核 |
| 已驳回 | 平台判违规或资料不足 | 按驳回原因修改内容后保存，系统自动重新提交；或使用「重新提审」申请复核 |

## 2. 编辑商品

### 2.1 内容编辑

- 入口：商品列表行内「编辑」。
- 字段三态：不填 / 清空 / 有值 —— 前端会把「没填」归一成「不改」，把空串当作「清空」。
  清空副标题、详情、详情图是允许的；清空必填项会被服务端拒绝。
- 内容变更会触发重新审核；编辑接口带版本号（乐观锁），并发编辑时旧版本会收到 409，
  刷新后重试即可，不会覆盖别人刚保存的内容。

### 2.2 改价 / 改库存

- 入口：商品列表行内「改价 / 库存」或编辑弹窗中的价格库存区。
- 改价改库存**不触发内容重审、不升版本**；但会同步更新商品列表的最低价 / 最高价。
- 价格边界由服务端校验（过低 / 过高会被拒绝）。
- 已下单订单使用下单时的价格快照，改价只影响新订单。
- 只有具备「商品改价 / 改库存」权限的店员才能操作；否则 403。

### 2.3 规格结构（SKU）

- 入口：商品列表行内「规格」。
- 保存是**全量集合语义**：提交后的规格就是最终的全部规格；新增 / 删除 / 改名 / 换图都会生效。
- **结构变化会重新审核并升版本**；只改价格 / 库存不重审。
- 已经有订单（或仍有冻结库存）的规格**禁止删除**；弹窗会提前标出「已有订单」。
- 规格数量范围 1~20 条。

## 3. 上下架、删除与回收站

### 3.1 单个上下架

- 商品列表行内「上架 / 下架」。
- 上架要求：店铺营业中、商品审核通过（第三方商品）。
- 下架不受审核状态限制（卖家随时可以撤下自己的商品）。

### 3.2 批量上下架

- 列表勾选商品 → 批量上架 / 下架，单次最多 100 件。
- 结果是**逐条**的：部分失败不会回滚已成功的条目；弹窗会列出每条的成败与原因。
- 需要「商品上下架 / 删除」权限。

### 3.3 删除与恢复

- 删除是**移入回收站（软删）**，不是物理删除；保留 30 天。
- 回收站内可「恢复」；恢复后为下架态，需要手动重新上架。
- 超过 30 天由系统清理；清理后不可恢复。
- 删除 / 恢复需要「商品上下架 / 删除」权限。

## 4. 复制、导入与导出

### 4.1 复制商品

- 商品列表行内「复制」：以现有内容与规格新建一件商品。
- 新商品标题追加「（副本）」（长度允许时），**默认下架**，销量与评分归零。
- 复制完成后请检查标题、主图、价格与库存，再上架。

### 4.2 导出 CSV

- 商品列表「导出」：一个规格一行，UTF-8 BOM，Excel 可直接打开。
- 导出内容是当前店铺商品（受列表筛选影响时以页面提示为准）。

### 4.3 导入 CSV

1. 先下载「导入模板」，按 16 列表头填写；同一商品的多条规格用同一分组键。
2. 单次限制：文件 ≤ 2MB、≤ 500 行、≤ 100 个商品分组。
3. 导入是**逐组独立事务**：某一组失败不影响其他组；返回结果会逐组列出成功 / 失败原因。
4. 导入属于「商品内容编辑」权限；只读店员不能导入。
5. 模板中的类目 ID、品牌 ID 需替换为平台实际存在的值；价格单位是元（系统会换算为分）。

> CSV 内容会做公式注入防护；以 `=`、`+`、`-`、`@` 开头的文本会被转义。

## 5. 商品诊断

- 入口：商品列表「商品分析」或商品详情内的诊断区。
- 指标：近 N 天曝光、点击、点击率、点击成交率（与交易域订单数据合并）。
- 默认近 30 天，最长 90 天。
- 建议按「先拦路、后优化」理解：
  - 曝光低 → 先检查类目、标题、主图、价格是否有竞争力；
  - 有曝光无点击 → 优化主图 / 标题 / 价格；
  - 有点击无成交 → 检查详情、规格、库存、运费与评价。
- 曝光与点击由商品域记录；成交 / 退款来自交易域，跨库不 JOIN，由前端按 spuId 合并。

## 6. 订单发货与售后

### 6.1 发货

1. 「订单管理」→ 找到已付款订单 → 「发货」。
2. 可手填物流公司与单号；也可使用「获取电子面单」自动生成模拟面单并回填。
3. 发货后订单进入已发货；资金仍托管，买家确认收货（或超时自动确认）后才放款。
4. 需要「订单发货」权限。

### 6.2 售后退款

- 已发货订单的退款由卖家在确认收到退货后发起；未发货订单买家可自助退款。
- 入口：订单详情 / 售后页「退款」。
- 需要「售后退款」权限。
- 售后页顶部有「退款商品 / SKU 统计」：按订单明细快照统计退款件数、退款金额与涉及订单数，
  用于判断是某个规格的质量问题还是偶发退款。

## 7. 评价管理

- 入口：「评价管理」。
- 只有审核通过的公开评价才会出现在商家列表；可按「已回复 / 未回复」「星级」「关键词」筛选。
- **一条评价只能回复一次**，回复后不可修改或删除；请确认措辞后再提交。
- 回复内容同样会过内容质检：命中联系方式、站外链接、导流话术等会被拒绝。
- 匿名评价只展示脱敏昵称，商家端看不到买家真实身份。

## 8. 店员与权限（F-04）

### 8.1 邀请与停用

- 「店员管理」→ 输入已注册手机号邀请；一个账号只能属于一家店。
- 停用即时生效：店员下一次请求就会被拒绝，不需要等令牌过期。
- 店主账号不可被停用。

### 8.2 配置权限

1. 店员行点击「权限」。
2. 勾选可执行的操作：
   - 商品内容编辑：发布 / 编辑 / 复制 / CSV 导入；
   - 商品改价 / 改库存：改价、改库存、规格结构保存（结构保存同时需要编辑权）；
   - 商品上下架 / 删除：上下架、批量、删除、恢复、提审；
   - 订单发货；售后退款；客服回复。
3. 全部不勾 = 仅查看（能看订单 / 商品 / 客服，不能做任何写操作）。
4. 保存后立即生效，无需店员重新登录。

### 8.3 常见误解

- 店员能看到的订单与商品是**全店范围**，权限约束的是「能做什么」，不是「能看什么」。
- 结算与提现对店员默认不可见，且没有开关。
- 权限修改会留审计记录（动作 `UPDATE_STAFF_PERMISSIONS`），可追溯「谁在什么时候放开了什么」。

## 9. 账号安全

- 「账号中心」可修改店铺名（仅营业中店铺）与开启两步验证。
- 开启两步验证后，商家端与商城登录都需要输入认证器验证码；手机丢失可用恢复码。
- 恢复码只展示一次，服务端只保存哈希；请离线保存。
- 需要关闭时，用当前验证码或一枚恢复码；关闭后账号只由密码保护。

## 10. 常见错误与处理

| 现象 | 常见原因 | 处理 |
|---|---|---|
| 403 当前店员账号没有「…」权限 | 店主未给该操作权限 | 店主在「店员管理 → 权限」勾选并保存 |
| 403 该账号不是卖家 | 未入驻 / 账号不是店主或店员 | 完成入驻；或让店主邀请为店员 |
| 404 商品 | 商品不属于本店 / 已删除进回收站 | 确认店铺归属；到回收站恢复 |
| 409 商品已被修改 | 并发编辑，版本过期 | 刷新详情后重新编辑 |
| 422 必填类目属性缺失 | 类目模板要求的属性未填 | 按发布页提示补齐属性 |
| 422 正在审核中 | 重复提交 | 等待审核结果；被驳回后修改会自动重提 |
| 422 规格已有订单不能删除 | 该 SKU 被订单或冻结库存引用 | 保留该规格，新增替代规格 |
| 导入部分失败 | 某组数据不合法 | 看逐组结果，修正后只重导失败组 |

## 11. 操作与接口对照（排障用）

| 操作 | 接口 |
|---|---|
| 商品列表 / 详情 | `GET /api/seller/products`、`GET /api/seller/products/{id}` |
| 发布 / 编辑 | `POST /api/seller/products`、`PUT /api/seller/products/{id}` |
| 上下架 / 批量 | `POST /api/seller/products/{id}/status`、`POST /api/seller/products/batch-status` |
| 改价改库存 | `PUT /api/seller/products/{id}/skus/price-stock` |
| 规格结构 | `PUT /api/seller/products/{id}/skus`、`GET /api/seller/products/{id}/skus/usage` |
| 删除 / 恢复 | `POST /api/seller/products/{id}/delete`、`/restore` |
| 复制 / 导出 / 导入 | `POST /api/seller/products/{id}/copy`、`GET /api/seller/products/export`、`POST /import` |
| 诊断 | `GET /api/seller/products/diagnostics` |
| 发货 / 退款 | `POST /api/seller/orders/{orderNo}/ship`、`/refund` |
| 退款统计 | `GET /api/seller/product-refunds` |
| 店员 / 权限 | `GET /api/seller/staff`、`POST /api/seller/staff/{memberId}/permissions` |
| 两步验证 | `GET /api/auth/2fa/status`、`POST /api/auth/2fa/setup|enable|disable` |

> 接口细节以 `docs/openapi/endpoints.md` 与各服务控制器为准；本手册只列商家常用入口。
