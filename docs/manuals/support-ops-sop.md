# 客服 / 运营 SOP（K-04）

> 适用站点：商家工作台客服 `http://merchant.localhost:8091/seller/support`；
> 买家客服 `/support`；平台后台 `http://admin.localhost:8090`
> 对应实现：C-01~C-05、H-01/H-02/H-03、E23、A-08、E18
> 最后更新：2026-10-26

---

## 第一部分 · 客服工作台

### 1. 会话列表与筛选

| 筛选 | 用途 |
|---|---|
| 全部 | 交接班、巡检、处理历史会话 |
| 未读 | 当班优先处理；未读数来自服务端，不靠前端猜 |
| 已关闭 | 回查历史；买家再发消息会自动重开 |

- 会话行会显示最后一条消息、时间、未读角标与当前处理人（未认领时显示「未认领」）。
- 点开会话即清零该会话未读；顶部导航角标会在下一轮轮询同步。
- 同一店铺的店主与在职店员都能看到全店会话；**处理人不是访问控制**。

### 2. 工单：认领 / 转交 / 释放

| 动作 | 谁可以操作 | 规则 |
|---|---|---|
| 认领 | 本店在职成员 | 并发认领只有一人成功；重复认领（已是本人）幂等；已被他人认领返回 409 |
| 转交 | 当前处理人或店主 | 目标必须是本店在职成员；可填备注；动作前处理人变化则失败 |
| 释放 | 当前处理人或店主 | 归还为未认领；重复释放幂等 |

- 每次成功动作都会写一条 append-only 处理记录（CLAIM / TRANSFER / RELEASE），
  包含前后处理人、操作者、备注与时间。
- 交接班标准动作：上一班把未完成会话「转交」给下一班并写备注；下一班先看「工单」里的处理记录再回复。
- 已关闭会话不能认领；买家再发消息自动重开后再认领。

### 3. 回复与内容质检

- 回复需要「客服回复」权限（店员可由店主配置；只读店员可以看会话但不能发言）。
- 内容质检规则（发送前拦截，命中即发不出去）：
  - 站外链接 / 域名 → 拦截；
  - 资金诈骗话术（转账、验证码、刷单返利等）→ 拦截；
  - 运营配置敏感词（默认含代练、外挂等）→ 拦截；
  - 手机号 / QQ / 微信号 → 默认**只告警不拦截**（售后沟通需要），配置可改为拦截。
- 被拦截的消息不会落库、不会推送；错误提示会说明风险类别，但不会展示完整词表。
- 不要尝试用空格、全角、拆字绕过质检；系统会做归一化，且绕过本身违反运营纪律。

### 4. 未读与已读

- 我方消息：对方未读时显示「未读 N 条」；对方打开会话后只在最后一条显示「已读」。
- 买家侧逐条「未读」为纯文字琥珀色标记；商家端同款。
- 未读数是**服务端口径**；不要用「最新一条消息」自行推断。

### 5. 关闭与重开

- 店主 / 店员可关闭已处理完的会话；关闭只是状态，不是删除。
- 买家再次发消息会自动重开，历史消息保留。
- 关闭后不要继续在旧会话里承诺新的处理时限；以重开后的新消息为准。

### 6. 标准话术

| 场景 | 建议话术 |
|---|---|
| 问候 | 「您好，我是多多宠物商店客服，请描述一下遇到的问题，我会尽快为您处理。」 |
| 催发货 | 「您的订单已付款，我们会在 48 小时内安排发货；发货后单号会同步到订单详情。」 |
| 物流停滞 | 「我帮您查一下物流节点；如果超过 72 小时没有更新，我们会联系快递核实。」 |
| 缺货 | 「这款暂时缺货，预计 X 月 X 日到货。您可以选择等待、换同价位规格，或申请退款。」 |
| 退款 | 「已收到您的退货申请。仓库确认收到并验货后，我们会在 1 个工作日内发起退款。」 |
| 质量问题 | 「抱歉给您带来不好的体验。请拍一下商品与包装的照片，我们核实后给您补发或退款。」 |
| 要求站外交易 | 「平台不支持微信 / 支付宝私下转账，请通过订单页完成支付，这样双方都有保障。」 |
| 索要手机号 | 「为了保护您的隐私，我可以在平台内沟通；如需电话联系，请留下方便的时间，我们通过平台外呼。」 |
| 投诉升级 | 「这个问题我记录下来并升级给店长处理，会在 24 小时内给您答复。」 |

> 话术只定基调，不要承诺无法兑现的时效或赔付；承诺必须与订单 / 售后实际状态一致。

### 7. 升级路径

| 情况 | 动作 |
|---|---|
| 买家情绪激动、涉及人身安全 | 先安抚，立即转交店主；必要时终止会话并保留记录 |
| 疑似诈骗 / 站外导流 | 不点击链接、不转账；保留截图；上报平台运营 |
| 涉及资金争议（重复付款、退款未到账） | 转交店主 → 平台售后仲裁；不要在会话里承诺「马上退」 |
| 商品质量批量问题 | 记录批次 / 规格，通知店主下架相关 SKU，按售后流程统一处理 |
| 平台规则不清 | 查本 SOP 与商品手册；仍不确定则上报运营，不自行解释规则 |

### 8. 交接班清单

1. 未认领会话：按紧急程度认领或转交；
2. 已认领未完成：写清楚「已做什么 / 还差什么 / 承诺了什么」再转交；
3. 资金 / 投诉类：单独列给店主；
4. 检查导航角标：未读客服、待发货、售后、待回复评价是否已清零或已交接。

## 第二部分 · 平台运营

### 1. 商品审核台

- 入口：后台「商品审核」。
- 查看全量背审材料：主图、图集、介绍、富文本详情、规格参数、包装、SKU 价格库存、类目 / 品牌。
- 结论：通过 / 驳回（驳回原因必填）；审核可重入（允许改判）。
- 通过后商品自动上架；驳回会置为下架并通知商家。
- 审核动作会写商品审核历史（A-08），目标商品与操作人可追溯。

### 2. 抽查复核（SLA）

- 入口：后台「抽查复核」。
- 对象是**已经自动放行、已在售卖**的商品；复核「放行判对了没有」。
- PASS 只记结论；REJECT = 驳回并强制下架（备注必填），同时累计商家违规。
- 抽查任务会记录「抽中时的版本」；商家后续编辑会造成版本漂移，界面只提示、不阻断。

### 3. 评价管理

- 入口：后台「评价管理」。
- 可按审核态、星级、关键词筛选；对违规评价执行下架 / 恢复。
- 下架原因必填；下架会立即影响公开评价区与商品评分 / 好评率。
- 机审自动通过的干净评价为 `AUTO`；命中风险的为 `PENDING`，需人工处理。
- 商家回复是一次性承诺，运营不要代商家修改回复内容。

### 4. 举报处理

- 入口：后台「举报处理」。
- 处置：通过 / 驳回 / 下架；每次处置留审计。
- 涉及违法内容时先下架再走外部流程，不要等商家申辩。

### 5. 订单干预

- 入口：后台「订单干预」。
- 强制关闭仅适用于待付款订单；已付款订单的关闭会触发退款，属资金动作，必须留原因。
- 代第三方店铺发货 / 售后需走代运营工单（E23），不能直接以平台身份改商家订单。

### 6. 售后仲裁

- 入口：后台「售后仲裁」。
- 用于买卖双方无法达成一致、或平台垫付 / 卖家欠款场景。
- 裁定结果决定退款与责任归属，属资金动作；必须写清依据。
- 平台垫付会登记卖家欠款；后续从结算中扣回。

### 7. 变更历史

- 入口：后台「变更历史」。
- 按商品 ID / 标题关键词 / 事件 / 店铺过滤，查看每条字段级改前改后。
- 用途：复盘「谁在什么时候把哪件商品改成了什么」；商品标题按**当前值**定位，旧标题看 diff。
- 事件包括：提交、编辑、重新提审、审核通过、审核驳回、抽检驳回。

### 8. 租户健康度

- 入口：后台「租户健康度」。
- 关注：接口错误率、超时、资金异常、违规累计、资质临期 / 过期。
- 资质过期会自动停业并联动下架商品；续期后需商家重新上架。
- 高风险租户先看明细再处置；封禁 / 停业属不可逆动作，必须留痕。

### 9. 审计日志

- 入口：后台「操作审计」。
- 记录「谁在后台做了什么」：角色变更、2FA、入驻审核、成员、商品审核、评价、订单、结算、对账等。
- 归 SECURITY / TENANT / CONTENT / FUNDS / OTHER 类目；资金与安全类不可删改。
- 排查顺序：先按动作 + 目标定位，再按租户与时间范围收窄。

## 第三部分 · 应急处置

### 1. 商品被误驳回

1. 商家按驳回原因修改后重新提交（自动进入待审核）；
2. 或商家点「重新提审」申请复核；
3. 运营在审核台看历史 diff，确认是误判后「通过改判」；
4. 全程留审核历史，不要直接改库。

### 2. 重复收款

- 当前为「检出 + 人工退款」，不做自动退。
- 先核对支付单与订单状态，确认重复后走退款；保留支付流水与操作记录。
- 不要删除订单或支付记录来「消除重复」。

### 3. 资质过期 / 自动停业

- 系统 T30 / T7 通知，EXPIRED 自动停业并联动下架商品。
- 商家续期并通过审核后，需手动重新上架商品。
- 运营不要手工改 `status` 绕过巡检；如需临时复业，走正式续期流程。

### 4. 店铺被封禁 / 违规累计

- 违规累计达到阈值会自动停业；平台也可人工处置。
- 处置前确认订单 / 售后 / 资金是否已清理；封禁不等于免除退款责任。
- 所有处置写审计；不要用「删除账号」代替停业。

### 5. 敏感内容 / 站外导流

- 客服消息命中即拦截；已发出的历史消息由商家自行撤回或平台按规则处理。
- 商品详情 / 评价命中风险由机审转 PENDING，运营下架并写原因。
- 涉及违法内容：先下架 / 关闭，再按公司流程上报。

## 第四部分 · 纪律与禁区

1. **不绕过门禁**：403 是权限边界，不要用其他账号 / 直接改库绕过；需要权限找店主配置。
2. **不动资金事实**：退款、结算、垫付、欠款核销必须走对应接口并留原因；
   严禁直接改 `t_order` / `t_payment` / `t_settlement` 的金额或状态。
3. **不删除审计**：审计与审核历史是 append-only；清理数据前先确认保留义务。
4. **不泄露买家身份**：商家端只应看到脱敏信息；不要把手机号、地址转发到外部。
5. **不私下交易**：客服会话中引导站外支付 / 转账属于违规，质检会拦截。
6. **承诺要可兑现**：时效、赔付、补发必须与订单 / 售后实际状态一致。
7. **交接要留痕**：工单转交必须写备注；口头交接不算完成。
