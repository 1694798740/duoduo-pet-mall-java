## 3. 症状 → 根因 → 正确做法（**排障先查此表**）

| # | 症状 | 根因 | 正确做法 |
|---|---|---|---|
| T-01 | `docker info` 无 Server 版本 | Docker Desktop 未启动（须人工） | 提示用户启动；不要尝试用 wsl 代启 |
| T-02 | 拉镜像报凭据助手错误 | 全局 docker 配置指向缺失的 credsStore | 用 `DOCKER_CONFIG=D:\duoduo-infra\docker-nocreds` |
| T-03 | 构建报无法解析依赖（aliyunmaven 404） | 用了全局 `settings.xml`（`mirrorOf=*` 指向已失效私服） | 用项目内 `maven/settings.xml` |
| T-04 | 单模块构建报缺 `duoduo-common` jar | 漏了 `-am` | `-pl <module> -am package` |
| T-05 | `mvn` / `mvn.cmd` 起不来 | 受限环境禁止 `cmd.exe` | 用 `java -classpath plexus-classworlds… Launcher`（命令见 AGENTS.md） |
| T-06 | 前端页面「没有权限执行该操作」，curl 复现不出 | 用了 `127.0.0.1:5173`，不在 CORS 白名单 | 用 `http://localhost:5173`；换来源要同步 `CORS_ORIGINS` |
| T-07 | 冒烟脚本一跑就语法报错 / 中文乱码 | `.ps1` 未存为 **UTF-8 with BOM** | 重存为 BOM；`head -c 3 file \| xxd` 校验为 `efbbbf` |
| T-08 | 中文断言「库里明明有，断言说没有」 | `docker exec mysql` 控制台 GBK | 库内只判状态/非空；中文走接口读回比对 |
| T-09 | 断言找不到刚写入的数据 | 19 位雪花主键经 `ConvertFrom-Json`/`JSON.parse` 丢精度 | 断言用**业务键**（订单号）；确需主键从**原始响应文本**正则提取 |
| T-10 | 服务端收到 `spuId = "=1&pageSize=50"` 类型转换错 | PS 5.1 把 `$SPU?page=1` 整体当变量名 | 一律写 `${SPU}?page=1` |
| T-11 | 断言失败信息像「过滤器坏了」，其实是 500 | 打错端口（连 8084 打用户域路径 → 无此路由） | 直连对端服务端口；**先确认打的是哪个服务** |
| T-12 | 新增端点编译通过但运行时 404/500 | 端点无内部引用，编译期发现不了（I-13） | 新增对外端点**必须实调一次**（curl 或冒烟） |
| T-13 | 创建类目/品牌报 `Column 'id' cannot be null` | `id-type: input` 未显式赋雪花 id | insert 前 `entity.setId(idGenerator.nextId())` |
| T-14 | 所有审核请求都 422 | 用对外动词（`APPROVE`）比库内状态（`APPROVED`） | switch 显式映射两层（INV-6） |
| T-15 | 停用的类目/品牌在后台消失、无法恢复 | 后台列表复用了只含 `ACTIVE` 的公开查询 | 后台走独立方法（`flatForAdmin` 等），DTO 带 `status` |
| T-16 | 客户端错误（错 Content-Type）返回 500 | 落到兜底 handler，未映射 415 | 已修 `UNSUPPORTED_MEDIA_TYPE`；新增客户端错误场景照此补映射 |
| T-17 | 页面显示「加载失败」但其实是没有数据 | 把空态当错误态 | 空数据是正常状态（`Empty`），只有请求失败才是 `Alert kind="error"` |
| T-18 | 页面每轮渲染都重发请求 | `useAsync` 依赖放了数组/对象（引用每轮变化） | 依赖只放 primitive（如 `orderNos.join(',')`） |
| T-19 | 改完 md 后 `git diff` 整个文件都是差异 | Python 在 Windows 默认按 CRLF 写文本 | 收尾统一回 LF：`open(p,'wb').write(open(p,'rb').read().replace(b'\r\n',b'\n'))` |
| T-20 | 腾讯文档写入长文报 `Argument list too long` | MCP 命令行参数上限 ~32KB | 用**进程内** `tencentdocs.call_tool`（见 `publish_handover.py`） |
| T-21 | 云端文档「大纲节数只有 1」 | `get_outline` 返回的是**根节点 + children 树** | 递归统计子节点（见 `verify_handover.py`） |
| T-22 | 乐享导入长文档时报 token 超限 | 把 60KB 正文塞进单次工具调用 | 用**子代理并行**分批导入，内容不进主会话上下文 |
| T-23 | 支付二维码扫出来打不开 | 二维码指向了服务直连端口（扫码设备不可达） | 必须指向**网关 8080**（`SANDBOX_CASHIER_URL`） |
| T-24 | 订单已取消，二维码还能付款 | 关单/取消路径未作废支付单 | 两条路径都要调 `markClosedByOrder`（已修，勿回退） |
| T-25 | 调内部接口拿到 **401**，但服务日志里看不到任何拒绝记录 | **走了网关**：`/internal/**` 不在白名单，网关按「未登录」先拦了一层，请求根本没到业务服务 | 内部接口一律**直连对端端口**（8081/8082/8083/8084）+ `X-Internal-Token`，不经网关。断言失败先确认「打的是哪个服务」（与 T-11/I-13 同源） |
| T-26 | 用 curl / 脚本 POST 一个「不用请求体」的接口，返回 **415** | 方法用了 `@RequestBody(required = false)`，而客户端（curl、部分 HTTP 库）默认带 `application/x-www-form-urlencoded`，Spring 找不到能把该 Content-Type 转成目标类型的转换器 → 415 | 运维类接口的开关参数**优先走查询串**（`?dryRun=true`），与既有 `?active=false` 写法一致；确实需要请求体时就要求客户端显式声明 `application/json` |

## 4. 明确禁忌（做过即视为不合格）

1. **不要**删除或改动 `.workbuddy/`（项目记忆、工具脚本、进度数据）。
2. **不要**修改既有断言使其通过；不要为了让冒烟绿而放宽业务校验。
3. **不要**在代码或文档里写入真实密钥/口令/令牌（只写变量名与用途）。
4. **不要**用 `rm -rf` / `docker compose down -v` 处理非开发环境数据（`-v` 会清空四库）。
5. **不要**跳过 Git hooks（`--no-verify`）或跳过 README 同步提交。
6. **不要**跨库 JOIN、跨服务直连数据库。
7. **不要**在请求处理器里跑长任务（用补偿调度/异步任务，见 `07` A11）。
8. **不要**在网关白名单里放写接口（INV-14）。
9. **不要**把令牌放进 URL 或 localStorage。
10. **不要**在没有冒烟覆盖的情况下交付跨服务改动。
