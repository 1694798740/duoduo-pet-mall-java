## 3. 症状 → 根因 → 正确做法（**排障先查此表**）

| # | 症状 | 根因 | 正确做法 |
|---|---|---|---|
| T-01 | `docker info` 无 Server 版本 | Docker Desktop 未启动（须人工） | 提示用户启动；不要尝试用 wsl 代启 |
| T-02 | 拉镜像报凭据助手错误 | 全局 docker 配置指向缺失的 credsStore | 用 `DOCKER_CONFIG=D:\duoduo-infra\docker-nocreds` |
| T-03 | 构建报无法解析依赖（aliyunmaven 404） | 用了全局 `settings.xml`（`mirrorOf=*` 指向已失效私服） | 用项目内 `maven/settings.xml` |
| T-04 | 单模块构建报缺 `duoduo-common` jar | 漏了 `-am` | `-pl <module> -am package` |
| T-05 | `mvn` / `mvn.cmd` 起不来 | 受限环境禁止 `cmd.exe` | 用 `java -classpath plexus-classworlds… Launcher`（命令见 AGENTS.md） |
| T-06 | 前端页面「没有权限执行该操作」，curl 复现不出 | 用了 `127.0.0.1:5173`，不在 CORS 白名单 | 用 `http://localhost:5173`；换来源要同步 `CORS_ORIGINS` |
| T-07 | 冒烟脚本一跑就语法报错 / 中文乱码 | `.ps1` 未存为 **UTF-8 with BOM** | 重存为 BOM；`head -c 3 file \| xxd` 校验为 `efbbbf` |
| T-08 | 中文断言「库里明明有，断言说没有」 | `docker exec mysql` 控制台 GBK | 库内只判状态/非空；中文走接口读回比对 |
| T-09 | 断言找不到刚写入的数据 | 19 位雪花主键经 `ConvertFrom-Json`/`JSON.parse` 丢精度 | 断言用**业务键**（订单号）；确需主键从**原始响应文本**正则提取 |
| T-10 | 服务端收到 `spuId = "=1&pageSize=50"` 类型转换错 | PS 5.1 把 `$SPU?page=1` 整体当变量名 | 一律写 `${SPU}?page=1` |

| T-14 | 所有审核请求都 422 | 用对外动词（`APPROVE`）比库内状态（`APPROVED`） | switch 显式映射两层（INV-6） |

| T-27 | 前端 dev server 起不来：`Error: listen EACCES: permission denied 127.0.0.1:5173`（**不是**端口被占，也**不是**沙箱拦的） | Windows **排除端口段**：Docker Desktop 启动后 WinNAT 会保留一批动态 TCP 端口，本机实测为 `4542-4741 / 4828-5027 / 5149-5348 / 50000-50059`，**5173 正落在 5149-5248 里**。排除段内的端口 listen 一律 EACCES | 查：`netsh int ipv4 show excludedportrange protocol=tcp`。改端口即可：`vite --port 3000`，并设 `UI_BASE=http://localhost:3000`。**3000 已在网关 `CORS_ORIGINS` 白名单内**（默认值就带 `http://localhost:3000`），无需改任何配置。以后 UI 自测起不了 dev server，先查排除段 |
| T-28 | PowerShell `Start-Process` 报「已添加项。字典中的关键字:"Path" 所添加的关键字:"PATH"」 | 当前会话环境里同时存在 `Path` 与 `PATH` 两个键（大小写不同、Windows 视为同键），`Start-Process` 构造子进程环境时撞键失败 | 别用 `Start-Process` 起常驻进程（dev server 等）：直接**以后台任务方式运行**（`run_in_background`）执行 `node …`；顺带避开「父会话退出把子进程带走」的另一个坑 |
| T-29 | 某个日志文件莫名涨到 GB 级，把磁盘写满 | **自引用写**：`Get-Content $log \| Out-File -FilePath $log -Append` —— `Get-Content` 是惰性读，`Out-File` 一边追加一边就又有新内容可读，形成无限增长 | 读和写**不要指向同一文件**。要「只留尾部」就先 `Out-String` 落进变量、再一次性 `WriteAllText`；或写入另一个文件名 |
| T-30 | `git push` / `git ls-remote` 返回 **exit 128 且一行输出都没有**（PowerShell 通道）；同一个仓库在 **Bash 通道**下正常 | 本机 git 的 `credential.helper=manager`（Git Credential Manager）在 PowerShell 工具的环境里起不来，连接在凭据阶段就断了，且不吐任何错误 | **git 的远端操作（`ls-remote` / `fetch` / `push`）一律走 Bash 通道**；本地操作（`add`/`commit`/`log`/`status`）PowerShell 没问题。判据：128 + 无输出，先换通道再查网络。另注：Bash 通道的 `ls`/`dirname` 等命令不可用，但 `git` 可用 —— 所以**别用 Bash 做文件列举** |
| T-31 | 冒烟脚本报 **「通过 N 项，失败 0 项」全绿**，但某条断言其实**从未执行**（日志里根本看不到它的输出行） | 多行**续行**写法把断言拆到了两行：`Check "…" (…) `\`\n    … -eq '…'`。续行后 `-eq` 落在新行行首，被 PowerShell 当成**参数名**（`-eq` 不是合法参数），参数绑定阶段抛异常 → 该断言被跳过。而外层用 `$ErrorActionPreference='Continue'`，异常没终止脚本，于是「跳过」被静默吞掉 | ① 断言尽量写在**一行**内；非要续行，让下一行以 `(` / `$` / 值开头，别让 `-eq`/`-ne`/`-and` 这类**运算符落在行首**。② 给脚本加**断言总数守卫**：把脚本里 `Check "` 的出现次数（正则 `^\s*Check "`）在结尾与「实际执行数 $pass+$fail」比对，不等就报失败 —— 任何一条被跳过都会让守卫亮红灯（`logistics-smoke.ps1` 已内置，新脚本照抄） |
| T-32 | `Write` 工具新建的 `.ps1` 一跑就中文乱码 / 语法被撞坏 | `Write` 工具落盘是 **UTF-8 无 BOM**，而 PowerShell 5.1 默认按 **GBK** 解析无 BOM 文件 —— 与 T-07 同源，但**新建**脚本时最容易整条踩中（既有脚本都带 BOM，照抄文件时不会遇到） | 新建 `.ps1` 后立刻**补写 BOM**：以 `UTF8Encoding($false)` 读入、`UTF8Encoding($true)` 写回；校验首 3 字节为 `239,187,191`。与 T-07 合并记忆：**任何 `.ps1` 落盘都必须 UTF-8 with BOM** |
| T-33 | 冒烟辅助函数（如 `Factor($x)`）取值恒为空，导致一批断言失败 | 响应对象是 `{status, body, …}`，业务数据在 **`body.data`** 下 —— 少了一层 `body`。把它抽成辅助函数时，`$resp.data.factors` 取不到（正确是 `$resp.body.data.factors`），而**原始响应无此错**，重构成函数后才暴露 | 辅助函数**统一接收整个响应对象**、内部显式走 `$resp.body.data`；别把「已解包一半」的对象传来传去。改辅助函数后**必须重跑整套**（一处改错会连坐多条断言） |
| T-34 | 用 `INSERT … SELECT … FROM t_order` 造夹具，**库里一行没插进去、也不报错** | 跨库场景下未写**库限定名**：`t_order` 在 `duoduo_trade`，而连接默认库是 `duoduo_fulfilment`，`SELECT` 打到不存在的表 —— MySQL 部分模式下返回 0 行而非报错，`INSERT` 于是插了 0 行，下游断言全假失败 | 跨库 SQL 一律写全限定名 **`duoduo_trade.t_order`**。造完夹具先 `SELECT COUNT(*)` 确认行数再往下跑（本仓**禁止跨库 JOIN**，仅测试夹具的 `INSERT…SELECT` 允许） |
| T-35 | 前端 `tsc` 报 `TS18048: 'X' is possibly 'undefined'`（`Record<K,V>` 取值处），`?? FALLBACK` 也压不住 | 开了 `noUncheckedIndexedAccess`：`Record<K,V>` 的下标访问返回 `V \| undefined`；若 FALLBACK 本身也来自同一个 `Record`，`?? LEVEL_TONE[k]` 仍是 `V \| undefined` | 兜底值用**独立声明的常量**（如 `const FALLBACK_TONE = {…}`，类型是非可空对象），`toneOf(k) = RECORD[k] ?? FALLBACK_TONE`。别在 `Record` 内部拿另一条 `Record` 项当兜底 |
| T-36 | 某断言恒失败、表现为「请求 403 / 请求没带上某个头」，但同一请求用 curl 手打却正常 | **PowerShell 函数签名与调用处实参个数不符时，多传的实参被静默丢弃**（进 `$args`，不报错）：`trade-smoke.ps1` 的 `Call` 只声明了 4 个参数，调用处却传了第 5 个 headers 哈希表 → 内部凭据头从未发出，内部批量 SKU 接口恒 403（连带 7 条断言失败）。其余 12 套脚本的 `Call` 都声明了 `[hashtable]$headers`，唯独它漏了 | 改脚本辅助函数时，**确保签名与所有调用处的实参个数一致**；传 headers 的函数体里要有 `if ($headers) { $params.Headers = $headers }`。排障判据：**「脚本失败、curl 正常」→ 先查脚本是否真的把该发的头发出去了**（可用一次「少一个头会 403」的反证确认） |

## 4. 明确禁忌（做过即视为不合格）

1. **不要**删除或改动 `.workbuddy/`（项目记忆、工具脚本、进度数据）。
2. **不要**修改既有断言使其通过；不要为了让冒烟绿而放宽业务校验。
3. **不要**在代码或文档里写入真实密钥/口令/令牌（只写变量名与用途）。
4. **不要**用 `rm -rf` / `docker compose down -v` 处理非开发环境数据（`-v` 会清空五库）。
5. **不要**跳过 Git hooks（`--no-verify`）或跳过 README 同步提交。
6. **不要**跨库 JOIN、跨服务直连数据库。
7. **不要**在请求处理器里跑长任务（用补偿调度/异步任务，见 `07` A11）。
8. **不要**在网关白名单里放写接口（INV-14）。
9. **不要**把令牌放进 URL 或 localStorage。
10. **不要**在没有冒烟覆盖的情况下交付跨服务改动。
