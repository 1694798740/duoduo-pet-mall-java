# 06 · 测试与验收门禁（AI 自测依据）

> 本项目**没有单元测试框架**，验收靠「端到端冒烟 + 真实浏览器自测」。这是刻意选择：
> 微服务的主要风险在跨服务契约、状态机、幂等与并发，mock 掉的单测测不出来。
> （若后续补单测，优先补：① 金额/佣金/退款计算；② 状态机迁移合法性。）

## 2. 断言的硬性写法约定（AI 必须遵守）

| 约定 | 原因（历史教训） |
|---|---|
| **用业务键断言**（订单号 / SPU 号），不用 19 位雪花主键 | `ConvertFrom-Json` / `JSON.parse` 会丢精度，出现「数据在库里、断言找不到」的假失败 |
| 确需主键时，从**原始响应文本**正则提取：`[regex]::Match($r.raw, '"id":(\d+)')` | 同上；`Call` 已返回 `raw` 字段备用 |
| 带查询串的 URL 一律写 `${SPU}?page=1` | PS 5.1 把 `$SPU?page` 整体当变量名，展开成 `=1&pageSize=50` |
| 中文内容断言走**接口读回**比对 | `docker exec mysql` 控制台是 GBK，直接比中文会假失败 |
| 库内断言只判**状态 / 非空 / 计数** | 同上 |
| 脚本含中文 → 存为 **UTF-8 with BOM** | PS 5.1 否则按 GBK 解析，直接语法报错 |
| 内部接口断言**直连对端服务端口**（8081/8082/8083/8084） | 连错端口得到「无此路由」的 500，会被误读成过滤器故障 |
| 状态码断言写清口径 | 参数错 400 / 业务规则 422 / 冲突 409 / 越权 403 / 不存在 404 |
| **基准要贴着被测操作取**（就在操作上一行取，而不是「本节开始前」或「建夹具之前」） | 基准跨越多步副作用会同时产生两种错：把无关变化算进被测操作（**假失败**），与同类反向变化互相抵消（**假通过**）。A1 首轮自测两种都踩到了 |
| **「应为 0 / 应为空」的断言必须同时判响应体存在**（`$null -ne $body.data -and ...`） | 请求失败时 `data` 为 `null`，`[int]$null -eq 0` 判定为真 → 断言**假通过**，把「请求根本没成功」伪装成「结果正确」（A1 首轮自测：接口返回 415，却被读成「扫描到 0 条」） |
| 验证一个「修复类」接口时，**必须同时有控制组** | 只断言「该补的被补上了」，无法证明「不该动的没被动」——控制组（已有数据原样不动）是这类接口唯一能自证的方式 |
| **UI 断言里不要用「页面文本不含某词」判断按钮消失** | 成功 toast 的文案往往就含那个词（如「已申请平台仲裁」），`includes` 恒为真 → 断言**假通过**。要判 `getByRole(...).count() === 0` |
| **Playwright `getByRole` 的 `name` 是子串匹配** | `{name:'处理'}` 会命中页签「待卖家处理」，点到的不是目标按钮 → 用 `exact: true` 并限定在行/容器内 |
| **弹窗里的按钮名取决于默认值** | 售后裁定弹窗默认「驳回」→ 按钮是「确认驳回」，不是「支持退款并执行」。先读组件实现再写选择器 |
| **脚本结尾加「断言总数守卫」**：比对 `^\s*Check "` 出现次数与「实际执行数 `$pass+$fail`」，不等即报失败 | 多行**续行**会把 `-eq` 顶到行首，被 PS 当成参数名 → 参数绑定抛异常、该断言被**静默跳过**，而脚本**仍报 0 失败**（`$ErrorActionPreference='Continue'` 不终止）。守卫能让「被跳过」当场现形（见 08 篇 **T-31**） |
| **断言尽量写在一行内**；非要续行，下一行以 `(`/`$`/值开头，别让 `-eq`/`-ne`/`-and` 这类运算符落在行首 | 同上 |

## 3. 每套脚本必须覆盖的六类场景（新脚本照此检查）

1. **正常路径**：核心功能返回 200 且数据落库；
2. **未登录 401**（网关拦截）与**越权 403**（服务端归属/角色校验）；
3. **参数边界**：越界值 4xx（如评分 0/6、图片超 9 张、非法排序）；
4. **状态冲突 409**：幂等重复、重复发货、重复追评；
5. **业务规则 422**：未完成订单评价、非法状态迁移；
6. **夹具复原**：结尾自证数据回到测试前（汇总数/库存/角色等）。

## 4. 运行与排障

```bash
# 接口冒烟（任一脚本）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\review-smoke.ps1

# 真实浏览器自测（先起 dev server；必须用 localhost，不能用 127.0.0.1）
cd frontend && node node_modules/vite/bin/vite.js --port 5173
cd .. && node scripts/e2e/review-ui-check.mjs        # 评价 20 项
node scripts/e2e/aftersale-ui-check.mjs             # 售后三端 44 项（买家→卖家→运营整条链）
```

**失败时按此顺序排查**（顺序很重要，能省大量时间）：
1. **确认打的是哪个服务/端口**（直连 vs 网关；8081~8084 别搞混）——历史上最常见的误判来源；
2. 看服务日志：`docker logs duoduo-app-<svc> --since 5m | grep -iE "ERROR|WARN"`，定位到具体异常与 `requestId`；
3. 用 `curl` 复现一次最小请求（绕开脚本，判断是实现错还是断言错）；
4. 断言错（脚本问题）与实现错（业务问题）**必须区分**并分别记录；
5. 修完**重跑整套**（不要只重跑单项，避免修一处坏一处）。
