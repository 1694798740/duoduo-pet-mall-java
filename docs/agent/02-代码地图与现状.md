### 2.7 `duoduo-fulfilment`（:8084）
**评价（M11/P2-1）**：`controller/ReviewController`（`/api/reviews`）· `service/ReviewService`（评价全部规则）·
`entity/ReviewEntity` · `mapper/ReviewMapper`（聚合 SQL）。

**售后仲裁（A3）**：`controller/AfterSaleController`（`/api/aftersales`，买家/卖家）·
`controller/AdminAfterSaleController`（`/api/admin/aftersales`，运营）· `service/AfterSaleService`（售后全部规则）·
`entity/AfterSaleEntity` · `mapper/AfterSaleMapper`（**5 个 CAS 条件更新**）· `dto/AfterSaleDtos` ·
`support/AfterSaleStatus`（状态机与文案的单一事实来源）。

**支撑件（两域共用）**：`support/OrderRefs`（订单号→稳定内部标识的哈希，**必须只有一处实现**）·
`support/ImageUrls`（图片直链校验与 JSON 读写，只收 http/https）·
`client/{OrderClient,UserClient}` + `client/dto/*`（**跨服务契约副本**，手写不共享 jar）·
`config/InternalCallConfig`（注入内部凭据）。

> ⚠️ `service/AfterSaleService` 里有本项目最需要读懂的一段顺序约定：**先让钱动、再改售后单状态**。
> 反过来会得到「售后单显示已退款、钱其实没退」这类最难查的账目分歧。
> 改它之前先读注释块，尤其「已完成订单为什么退不了（B-01）」「为什么缺说明判 422 而不是 400」两处。
