# 03 · 架构与不变式（改动前必读）

> 本文件分两部分：**架构事实**（东西在哪、怎么连）与**不变式**（绝不能破的规则）。
> 不变式部分是历史缺陷换来的，每条都能在 `docs/PLAN.md` 问题区找到对应 I-xx 记录。

## 1. 架构事实

### 1.1 拓扑与端口
```
客户端(浏览器/小程序) ──▶ duoduo-gateway :8080  ← 唯一对外入口（鉴权/路由/CORS/身份透传）
                                   │ lb://（Nacos 服务发现）
        ┌──────────────┬───────────┼────────────┬──────────────┐
   duoduo-user    duoduo-product  duoduo-trade  duoduo-fulfilment
     :8081            :8082           :8083           :8084
        └──────────────┴───────────┴────────────┴──────────────┘
                MySQL :3306（四库，各服务只连自己的库）  Redis :6379
```

### 1.2 服务间调用（矩阵，改跨域逻辑时照此）
| 调用方 | 被调方 | 接口 | 用途 | 保护 |
|---|---|---|---|---|
| trade | product | `/api/products/internal/skus/batch` | 取 SKU 快照（价格/可售/卖家归属） | `X-Internal-Token` |
| trade | product | `/api/products/skus/stock/{freeze,release,deduct,restock}` | 库存冻结与释放 | `X-Internal-Token` |
| trade | （自身，运营/运维入口） | `/api/orders/internal/{orderNo}/{refund}`、`/internal/sweep` | 代运营退款、手动补偿调度 | `X-Internal-Token` |
| fulfilment | trade | `/api/orders/internal/{orderNo}/fact` | 评价资格校验（订单事实） | `X-Internal-Token` |
| fulfilment | trade | `/api/orders/internal/{orderNo}/refund` | **售后裁定通过后执行退款**（A3）—— 复用既有的运营侧退款入口，不新开资金通路 | `X-Internal-Token` |
| fulfilment | user | `/api/users/internal/briefs?ids=` | 批量昵称头像 | `X-Internal-Token` |

**调用姿势**（照抄，别自创）：Feign `@FeignClient(name="duoduo-<svc>", path="...")` + `InternalCallConfig` 统一注入请求头；
**不经网关**（网关是对外入口，绕它一圈会多一跳且放大故障）。

### 1.3 数据边界
- 每服务**只连自己的库**，禁止跨库 JOIN、禁止跨服务直连数据库。
- 需要别人的数据 → 调它的内部接口（只读、裁剪字段）。
- 表结构变更 → 改模块内 `src/main/resources/db/schema.sql` → 重新生成 `docs/sql/0X-*.sql` → 容器实际执行。

## 2. 不变式（INVARIANT — 违反即为缺陷）

| ID | 不变式 | 为什么（历史教训） | 怎么验证 |
|---|---|---|---|
| INV-1 | **幂等靠唯一索引**，不靠「先查再插」、不引入分布式锁 | 先查再插在并发下必然漏；本项目下单/支付/评价三处都靠唯一键兜底 | 新增写接口必须回答「幂等键 + 唯一索引名」 |
| INV-2 | **库存可售 = `stock - frozen_stock`**，扣减走**原子条件更新**（判断写进 WHERE） | 曾因「读-改-写」在并发下超卖 | `StockService` / `t_sku` 相关 SQL |
| INV-3 | **先落支付单再扣库存**，回调入账 = 验签 + 金额核对 + CAS 幂等 | 顺序反了会产生「扣了库存但没入账」 | `OrderService.pay` / `handleChannelCallback` |
| INV-4 | **补偿要按「逐项结果」精确记录**，不能只在整批成功时记录 | 部分成功时已冻成功的 SKU 被漏记 → 库存永久冻结（幽灵冻结） | `OrderService` 冻结补偿段 |
| INV-5 | **订单状态迁移只走状态机**（`OrderStatus`），所有迁移写 `t_order_status_log` | 曾出现「已付款可自助取消」这类非法边 | 新增状态相关接口时对照状态枚举 |
| INV-6 | **对外的动作动词 ≠ 库内状态值**（APPROVE→APPROVED / REJECT→REJECTED…） | 曾用动词直接比状态导致所有审核 422 | 审核类 service 的 switch |
| INV-7 | **后台列表不得复用「只含 ACTIVE」的公开查询** | 曾导致停用项消失、无法恢复 | 后台列表走独立方法（如 `flatForAdmin`） |
| INV-8 | **写接口的归属只认登录态**，请求体/路径**不接受** `userId`/`sellerId` | 接受即等于开放越权 | grep 新增 DTO 是否含这两个字段 |
| INV-9 | **服务间只读接口必须裁剪字段** | 曾把整份 OrderView（含收货人信息）返回给履约域 | 新内部接口返回 DTO 里不得出现 `receiver*` / `phone` |
| INV-10 | **400 与 422 分清**：参数格式/取值错 = 400 `VALIDATION_ERROR`；业务规则不满足 = 422 `BUSINESS_RULE` | 混用会让真 bug 淹没在业务分支里 | 新增异常用 `BizException.validation` vs `businessRule` |
| INV-11 | **内部接口失败关闭**：`InternalTokenFilter` 配置为空即拒绝 | 「没配就放行」会把配置遗漏变成线上越权 | 三个 filter 的实现 |
| INV-12 | **金额一律整数分；时间一律 UTC**；对外时间 ISO-8601 字符串 | 浮点金额会累积误差；时区错会导致过期判断错 8 小时 | 新增字段类型检查 |
| INV-13 | **`id-type: input` 的模块（含 product/trade/fulfilment）insert 必须显式赋雪花 id** | 曾因未赋值报 `Column 'id' cannot be null` 500 | 新表 insert 必须过冒烟 |
| INV-14 | **网关白名单按路径匹配（不看方法）** → 需登录的接口不得放在白名单前缀下 | 曾把写接口放进 `product/**` 白名单的潜在风险 | 新增白名单项时确认该前缀下无写接口 |
| INV-15 | **中文写入必须显式 `SET NAMES utf8mb4`**（初始化 SQL 与脚本） | 曾因 latin1 执行导致中文双重编码、检索 0 命中 | `docs/sql/*.sql` 首行 |

## 3. 工程约定（写代码时保持一致，不强制等价于不变式）

| 项 | 约定 |
|---|---|
| 分层 | Controller 薄（≤5 行）→ Service 业务规则 → Mapper 数据访问；Controller 不写业务逻辑 |
| 校验 | 入口用 Bean Validation 注解；**服务层再校一次**（服务可能被内部调用） |
| 事务 | 多步写入用 `@Transactional`；跨服务不做分布式事务（用补偿） |
| 日志 | 结构化 JSON，带 `requestId`；**不记录**密码/令牌/密钥/收货人隐私 |
| 配置 | 全部来自环境变量 + 默认值；生产要求见 `08` 篇 |
| 注释 | **写清「为什么这么做」**（本项目注释是实现理由的主要载体，评审依赖它） |
| 命名 | 对外动词与库内状态分离；常量集中在 support/enums |
| 页面 | 三态齐全（加载/空/错误）；空数据不是错误；4xx 不重试、5xx 重试 ≤3 |

## 4. 修改架构时的注意

- **新增服务**：POM 入父反应堆 → 选一个未用的雪花 `worker-id` → 三档配置（默认/local/mysql）→ 复用根 `Dockerfile` →
  `docker-compose.yml` 加容器 → 网关 `application.yml` 加路由（**默认不进白名单**）→ 冒烟脚本 → 文档（README §二 + 02 篇）。
- **新增跨域调用**：先在对端加**内部只读接口**（裁剪字段）→ 本端加 Feign client + 复用 `InternalCallConfig` →
  在 `04-接口契约全集.md` 的矩阵里登记 → 冒烟里断言「无凭据 403 / 有凭据 200 / 不含敏感字段」。
- **新增网关白名单**：只加**只读**路径；写完在冒烟里断言「未登录访问该路径 200、未登录访问同域写接口 401」。
