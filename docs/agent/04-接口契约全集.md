## 1. 全局约定

### 1.1 响应包络（所有接口）
```json
{ "code": "SUCCESS", "message": "ok", "data": <T | null>, "requestId": "hex", "timestamp": 1789700721253 }
```
分页：`data = { "items": [...], "total": n, "page": 1, "pageSize": 10, "pageCount": k }`（`page` 从 **1** 起）。
时间：**ISO-8601 UTC 字符串**（如 `"2026-09-18T03:51:24Z"`）。金额：整数**分**。

### 1.2 认证
| 头 | 由谁写入 | 说明 |
|---|---|---|
| `Cookie: access_token` / `refresh_token` | 服务端 Set-Cookie（httpOnly） | 前端**不**在 JS 里读令牌 |
| `X-User-Id` / `X-User-Phone` / `X-User-Role` | 网关校验令牌后注入 | 服务端从 `UserContext` 取；**客户端伪造的同名头会被网关剥离** |
| `X-Internal-Token` | 服务间调用（`InternalCallConfig`） | 校验方：user / product / trade 各自的 `InternalTokenFilter` |

### 1.3 错误码 ↔ HTTP（`ErrorCode` 全集）
| code | HTTP | 使用场景 | 构造方式 |
|---|---|---|---|
| `SUCCESS` | 200 | 成功 | — |
| `BAD_REQUEST` | 400 | 通用客户端错误 | — |
| `VALIDATION_ERROR` | 400 | 参数格式/取值不合法 | `BizException.validation(msg)` |
| `UNSUPPORTED_MEDIA_TYPE` | 415 | Content-Type 不对（历史缺陷：曾落 500） | 全局处理器 |
| `UNAUTHORIZED` | 401 | 未登录/令牌过期 | `BizException.unauthorized(msg)` |
| `FORBIDDEN` | 403 | 无权限（非运营/非本人/内部凭据错） | `BizException.forbidden(msg)` |
| `NOT_FOUND` | 404 | 资源不存在 | `BizException.notFound("订单")` |
| `CONFLICT` | 409 | 状态冲突/唯一键撞键（重复评价、重复发货） | `BizException.conflict(msg)` |
| `BUSINESS_RULE` | 422 | 业务规则不满足 | `BizException.businessRule(msg)` |
| `STOCK_INSUFFICIENT` | 422 | 库存不足 | 库存服务 |
| `ORDER_STATUS_ILLEGAL` | 422 | 状态机不允许 | 订单服务 |
| `PAYMENT_SIGNATURE_INVALID` | 401 | 回调验签失败 | 支付域 |
| `PAYMENT_CHANNEL_UNKNOWN` | 422 | 未知渠道 / MOCK 回调被拒 | 支付域 |
| `PAYMENT_AMOUNT_MISMATCH` | 422 | 回调金额与支付单不一致 | 支付域 |
| `RATE_LIMITED` | 429 | 限流（预留） | — |
| `DEGRADED` | 503 | 依赖不可用已降级 | — |
| `INTERNAL` | 500 | 兜底（**客户端错误落这里即为缺陷**） | 全局处理器 |

| 仲裁结论 | `t_after_sale.arbitrate_result` | `APPROVE_REFUND` / `REJECT` | 支持退款（**即执行退款**）/ 驳回 |

### 6.2 售后仲裁（A3，`/api/aftersales`）

| 方法 | 路径 | 认证 | 请求 → 响应 |
|---|---|---|---|
| POST | `/api/aftersales` | 登录（**仅本人订单，仅 `SHIPPED`/`COMPLETED`**） | `AfterSaleCreateRequest` → `AfterSaleView` |
| GET | `/api/aftersales/mine?status=&page=&pageSize=` | 登录 | → `PageResult<AfterSaleView>` |
| GET | `/api/aftersales/seller?status=&page=&pageSize=` | 登录（**卖家或运营**） | → `PageResult<AfterSaleView>` |
| GET | `/api/aftersales/{id}` | 登录（当事人或运营） | → `AfterSaleView` |
| POST | `/api/aftersales/{id}/reply` | 登录（**该单卖家**） | `AfterSaleReplyRequest` → `AfterSaleView` |
| POST | `/api/aftersales/{id}/escalate` | 登录（**该单买家**） | → `AfterSaleView`（申请平台仲裁） |
| GET | `/api/admin/aftersales?status=&page=&pageSize=` | 运营 | → `PageResult<AfterSaleView>` |
| POST | `/api/admin/aftersales/{id}/arbitrate` | 运营 | `AfterSaleArbitrateRequest` → `AfterSaleView` |

DTO（源：`fulfilment/dto/AfterSaleDtos.java`）：
| 类型 | 字段 |
|---|---|
| `AfterSaleCreateRequest` | `String orderNo; String type; String reason; List<String> images`（请求体**无** buyerId/sellerId/status） |
| `AfterSaleReplyRequest` | `String action; String reply` |
| `AfterSaleArbitrateRequest` | `String result; String note` |
| `AfterSaleView` | `Long id; String orderNo; Long buyerId; Long sellerId; String type; String typeLabel; String reason; List<String> images; String status; String statusLabel; String sellerReply; String arbitrateResult; String arbitrateNote; Long refundAmount; String createdAt; String updatedAt`（**不含** `arbitratedBy`：裁定人属平台内部信息） |
| 跨域契约副本 | `client/dto/RefundRequest.java`、`client/dto/RefundResult.java`（与交易域 `OrderDtos` 对齐） |

**售后业务规则（实现约束，改前先读 `AfterSaleService`）**：
归属与订单状态取自订单事实（内部接口），请求体无从伪造；仅 `SHIPPED`/`COMPLETED` 可立案（否则 422）；
唯一键 `(order_id, type)` → 同单同类型重复立案 409（**不同类型可各自立案**）；
卖家只能处理 `seller_id = 自己` 的单（403），拒绝必填说明（422）；
买家可从 `PENDING` 或 `SELLER_REJECTED` 申请仲裁（卖家拖着不处理时买家要有路走）；
运营裁定**必填说明**（缺 422），`APPROVE_REFUND` 会真的执行退款；
**顺序：先让钱动、再改售后单状态**；钱动失败时售后单保持原状态 —— 已完成订单（钱已放款）裁定退款会被交易域拒 **422**（需走追偿 / 平台垫付，见 `PLAN.md` B-01）；
状态迁移一律 CAS 条件更新（并发下卖家点同意与运营点裁定只有一次生效）。

> ⚠️ **`AfterSaleView.id` 是 `String`，不是数字**（2026-09-18 第十轮修正）。
> 售后单主键是 18 位雪花值（如 `359291401479008256`），**超过 JS `Number.MAX_SAFE_INTEGER`**，
> 前端 `JSON.parse` 会静默改写成另一个数，拿它拼 `/api/aftersales/{id}` 必然打到不存在的单子。
> 因此对外一律以字符串传，前端 URL 里也是完整的 18 位串。
> 新增「64 位 id 需要出到前端」的接口时照此办理；**别在前端用 `Number(id)` 转换**。

## 7. 前端 ↔ 后端映射要点（`frontend/src/api/`）
| 前端 | 后端 |
|---|---|
| `client.ts` 解包 `data`，并保留 `requestId` 供报错定位 | 所有接口统一包络 |
| 401 → 单飞刷新令牌并重放请求（`/api/auth/refresh`） | 令牌在 httpOnly Cookie |
| 5xx/网络错误退避重试 ≤3 次；4xx 不重试 | 错误码表见 §1.3 |
| 分页组件直接消费 `page/pageSize/pageCount/total` | `PageResult` |
| **雪花 ID 一律按业务键使用**（订单号/SPU 号），确需主键时从原始响应文本正则提取 | ID 为 19 位 bigint，JS `JSON.parse` 会丢精度 |
