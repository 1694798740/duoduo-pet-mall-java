# 05 · 开发任务手册（照抄即可）

> 六个配方覆盖本项目 95% 的开发场景。每个配方给「步骤 + 代码骨架 + 必查项」。
> 骨架里的注释是**理由**，不要删；本项目评审看注释判断你是否理解。

## R1 · 新增一个接口（同服务内，最常见）

**步骤**
1. 在 `dto/XxxDtos.java` 加请求/响应 `record`（字段名即契约，见 04 篇）。
2. `service/XxxService` 写业务规则（**全部规则在这里**），多步写库加 `@Transactional`。
3. `controller/XxxController` 挂薄方法（≤5 行）。
4. 需要登录 → 从 `UserContext.requireUserId()` 取；需要运营 → `OperatorGuard.requireOperator()`。
5. 编译 → 重建容器 → **在对应冒烟脚本里加断言**（正例 + 至少一个反向例）。
6. 同步 04 篇 + README §三。

**骨架**
```java
// ---- Service：业务规则集中在此 ----
public ReviewView append(Long userId, Long reviewId, String content) {
    if (userId == null) {                                  // 身份来自登录态，绝不来自参数
        throw BizException.unauthorized("请先登录");
    }
    ReviewEntity entity = reviewMapper.selectById(reviewId);
    if (entity == null) {
        throw BizException.notFound("评价");                 // 不存在 404
    }
    if (!userId.equals(entity.getUserId())) {
        throw BizException.forbidden("只能追评自己的评价");   // 越权 403（与 404 刻意区分）
    }
    if (entity.getAppendContent() != null) {
        throw BizException.conflict("每条评价只能追评一次");   // 状态冲突 409
    }
    // ... 业务规则；参数不合法用 validation() → 400，规则不满足用 businessRule() → 422
}

// ---- Controller：只有三件事 ----
@PostMapping("/{id}/append")
public ApiResponse<ReviewView> append(@PathVariable Long id,
                                      @Valid @RequestBody ReviewAppendRequest request) {
    return ApiResponse.ok(reviewService.append(UserContext.requireUserId(), id, request.content()));
}
```

**必查项**：① 请求体里没有 `userId`/`sellerId`（INV-8）；② 状态类错误用 409、规则类用 422（INV-10）；
③ 新增接口后**实调一次**（历史上出现过「编译通过但运行时 404」，见 `08` 篇 T-13）。

## R2 · 新增一张表 / 加字段

1. 改模块内 `src/main/resources/db/schema.sql`（**这是源文件**）。
2. 重新生成容器初始化脚本：`docs/sql/0X-duoduo-<svc>.sql`（改表头注释保持一致，首行 `SET NAMES utf8mb4`）。
3. 已有数据卷时 initdb **不会重跑** → 手工在运行库执行：
   ```bash
   docker exec -i duoduo-mysql mysql -uroot -p<root密码> --default-character-set=utf8mb4 < docs/sql/0X-....sql
   # 或仅执行 ALTER：docker exec duoduo-mysql mysql -uduoduo -pduoduo -D duoduo_trade -e "ALTER TABLE ..."
   ```
4. 实体加字段 + Mapper（MyBatis-Plus 驼峰映射已开）。
5. **insert 必须显式赋雪花 id**（`id-type: input`，INV-13）。
6. 唯一键/索引要写进 DDL 注释说明「为什么是这个键」（幂等？查询模式？）。
7. 冒烟里断言落库（**中文内容一律走接口读回**，别用 `docker exec mysql` 的 GBK 控制台比对）。

## R3 · 新增跨服务只读调用

1. **对端**先加内部只读接口：路径含 `/internal/`（会被对端 `InternalTokenFilter` 保护），
   返回**裁剪过的新 DTO**（不得含收货人/手机号/实名等，INV-9）。
2. **本端**加 `client/XxxClient.java`：
   ```java
   @FeignClient(name = "duoduo-trade", path = "/api/orders")   // 走 Nacos，不经网关
   public interface OrderClient {
       @GetMapping("/internal/{orderNo}/fact")
       ApiResponse<OrderFact> fact(@PathVariable("orderNo") String orderNo);
   }
   ```
   并在本端 `client/dto/` 放**契约副本** record（字段名与对端对齐，不对端共享 jar，避免联动发版）。
3. 复用 `config/InternalCallConfig`（已注入 `X-Internal-Token`），**不要**手写请求头。
4. 调用处处理三类失败：`FeignException.NotFound` → 404；其它 4xx/5xx → 明确降级策略
   （**不允许「对端不可用就放行」**，例如评价资格校验失败必须拒绝写入）。
5. 在 04 篇 §服务间调用矩阵登记，并在冒烟里断言：无凭据 403 / 有凭据 200 / 响应不含敏感字段。

## R4 · 新增前端页面

```tsx
// 1) api/types.ts：字段名与 Java DTO 逐字对齐
export interface XxxView { id: number; title: string; statusLabel: string }

// 2) api/endpoints.ts：加进对应域对象
export const xxxApi = {
  list: (query?: { page?: number }) => api.get<PageResult<XxxView>>('/api/xxx', { query }),
};

// 3) 页面：三态齐全（加载 / 空 / 错误），空数据不是错误
const { data, loading, error } = useAsync<PageResult<XxxView>>(
  useCallback(() => xxxApi.list({ page }), [page]),
  true,
  [page],                       // 依赖只放 primitive（数组/对象引用每次都变 → 每轮重发请求）
);
if (loading) return <LoadingBlock />;
if (error) return <Alert kind="error">{error}</Alert>;
if (data?.items.length === 0) return <Empty icon="📦" title="还没有数据" />;
```
4. `App.tsx` 挂路由（需登录包 `RequireAuth`；角色页加 `RequireSeller`/`RequireOperator`）。
   **公开落地页可不套 `RequireAuth`** —— 例：`/coupons` 领券中心（未登录也看得到有什么券，点「立即领取」时才引导登录，
   取舍见 `06` 篇）。
5. 入口挂到 `components/Layout.tsx` 或「我的」页快捷入口。
6. 必跑 `tsc --noEmit` + `vite build`；UI 走查用 `scripts/e2e/*.mjs` 的模式加一段
   （**e2e 夹具的 SQL 必须交给 PowerShell 执行，不能放在 Node 里**，见 `08` 篇 T-38）。
7. **前端只做体验拦截，权限边界必须在后端**（前端守卫只校验登录）。

## R5 · 新增一套冒烟脚本（或给现有脚本加断言）

**必须遵守的四条约定**（违反会被认为破坏测试纪律）：
1. 随机手机号生成夹具（可重复执行）；
2. 夹具数值（价格/库存/佣金）**从接口动态取**，不硬编码；
3. 改库前记录原值、结尾复原并自证（或自建自毁）；
4. 断言用**业务键**（订单号），雪花主键一律从**原始响应文本**正则提取。

**骨架（PowerShell 5.1，文件必须存为 UTF-8 with BOM）**
```powershell
function Call([string]$method, [string]$uri, $session, $bodyObj, [hashtable]$headers) { ... }  # 返回 @{status;body;raw}
function Check([string]$name, [bool]$ok, $extra) { ... }                                      # 统一 PASS/FAIL 计数

$r = Call 'Get' "$Gateway/api/reviews/product/${SPU}?page=1&pageSize=50" $anon $null $null    # 注意 ${SPU}? 写法
Check "公开列表能查到该评价" (@($r.body.data.items | Where-Object { $_.orderNo -eq $orderNo }).Count -eq 1) $r.body.data.total
```
必覆盖：**未登录 401 / 越权 403 / 参数越界 4xx / 幂等重复 409 / 业务规则 422 / 数据落库 / 夹具复原**。
执行：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts\xxx-smoke.ps1`

## R6 · 新增一个微服务（如 duoduo-marketing）

> **本配方已有一个现成参照**：A5 优惠券营销就是按本清单落地的 `duoduo-marketing`（:8085），
> 第 6 个业务服务 / 第 9 个容器，可直接对照该模块。
> **更贴近「新服务」的参照是 A9**：`duoduo-ai`（:8086）第 7 个业务服务 / 第 10 个容器 ——
> 它示范了**无状态服务**的写法（不引入 mybatis-plus / 不建库、不落对话历史，只经 Feign 取对端数据），
> 以及「外部依赖缺失时如实降级（503 `DEGRADED`）」而不是假装成功。

清单（对齐既有服务的做法，逐项照做）：
1. `pom.xml` 父反应堆加模块；新建模块 POM（依赖 `duoduo-common`、`duoduo-common-web`、web/validation/actuator、nacos-discovery、openfeign+loadbalancer、mybatis-plus、h2、mysql）。
2. `XxxApplication`（`@EnableDiscoveryClient`、`@EnableFeignClients(basePackages=...)`、`@MapperScan`）。
3. `config/XxxServiceConfig`：分页插件 + `SnowflakeIdGenerator`（**挑一个未用的 worker-id**：已用 1/2/3/4/5 = 用户/商品/交易/履约/**营销**）。
4. `resources/application.yml` + `application-local.yml`（H2 + 关 Nacos）+ `application-mysql.yml`。
   **端口环境变量用服务专属名**（如 `DUODUO_MARKETING_PORT`）**而不是通用名** `MARKETING_PORT` ——
   宿主机若已有同名通用变量，会静默把端口改掉，且只在容器内可见（A5 的取舍）。
4. `resources/application.yml` + `application-local.yml`（H2 + 关 Nacos）+ `application-mysql.yml`。
5. `resources/db/schema.sql`；`docs/sql/0N-duoduo-xxx.sql`；`00-init-databases-and-user.sql` 加库与授权。
6. `docker-compose.yml` 加容器（镜像名 `duoduo/duoduo-xxx:1.0.0`，端口、DB_URL、NACOS_*、INTERNAL_TOKEN、`depends_on`）。
7. 网关 `application.yml` 加路由（默认**不进白名单**）。
8. `support/InternalTokenFilter`（若有内部接口）+ `config/InternalCallConfig`（若调别人）。
9. 冒烟脚本 + 文档（README §二/§三 + `02`/`04` 篇 + `.env` 变量表）。
10. 更新 `docker-compose` 数量口径（README 中的「N 容器」）与 `03` 篇跨域矩阵。
