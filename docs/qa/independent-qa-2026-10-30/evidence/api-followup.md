# 独立 API 测试复盘：3 个原始 FAIL 的定性

`api-tests.py` 原始结果：17 用例，14 PASS / 3 FAIL（见 `api-tests.log`、`api-results.json`）。
逐条复核后，3 个 FAIL 均**不是产品缺陷**；其中 1 个（T15 跨人）已用补充实验完成验证。

## T12 同一券重复领取：产品行为是“幂等成功”，测试假设错误

- 原始结果：第一次 200，第二次也 200（`code=SUCCESS`）。
- 复核：`CouponService.claim` 对“已领过”走幂等快路径，返回同一张券（`alreadyClaimed=true`），不新增券。
- 回库：`t_coupon` 中该用户 + 模板 5001 只有 **1 行**（id `374231094997962752`），模板 `claimed_count` 从 97→98。
- 结论：**PASS（幂等）**，不是重复领券漏洞。测试用例应断言“第二次返回同一 coupon code / alreadyClaimed=true”，而不是断言 4xx。
- 清理：已删除该测试券并把 `claimed_count` 还原为 97。

## T14 伪造 AI 加购确认令牌：HTTP 200，但业务体是失败

- 原始结果：`HTTP 200` + 外层 `code=SUCCESS`。
- 复核响应体：

```json
{"code":"SUCCESS","data":{"success":false,"code":"CONFIRM_INVALID","message":"确认已过期，请重新确认",...}}
```

- 结论：服务端**确实拒绝了伪造令牌**；这是“外层 HTTP 成功、内层业务失败”的契约。测试应断言 `data.success=false && data.code=CONFIRM_INVALID`。
- 风险：只检查 HTTP 状态码的调用方会误判成功（见 code-risks.md CR-03）。

## T15 异步导出跨人下载：403 是因为第二个账号不是运营，补实验后 404 通过

- 原始结果：创建人下载 200；第二个账号下载/详情 403。
- 复核：第二个账号（手机号 `136****6850`）在数据库中的角色是 **USER**（`docs/test-accounts.md` 写的是 OPERATOR，文档过时），403 是运营门禁正常拒绝，不是任务归属逻辑。
- 补充实验：临时把买家 B（`371232604642480128`）改为 OPERATOR 并重新登录，访问同一任务：
  - `GET /api/admin/export-jobs/374231095450939392` → **404 导出任务不存在**
  - `GET /api/admin/export-jobs/374231095450939392/download` → **404**
  - 实验后已把买家 B 角色还原为 USER，删除任务行与导出文件。
- 结论：**跨人 404 通过**；T15 原 FAIL 是测试账号前置错误。
