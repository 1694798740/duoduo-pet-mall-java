# 图片资源优化配置方案（CDN / 生命周期 / 防盗链 / 压缩）

> 2026-10-21 制定。适用对象：`duoduo-mall-public-1374887902`（公有读）、
> `duoduo-mall-private-1374887902`（私有），地域 `ap-guangzhou`。

## 0. 结论与落地顺序

四件事的阻塞程度完全不同，**不能当成一批做完**：

| 事项 | 现状 | 阻塞点 | 谁能做 |
|---|---|---|---|
| **图片压缩** | **已落地并实测生效** | 无 | 已完成 |
| 生命周期规则 | 待配置 | 现有 AK 无桶配置权限（`GET ?lifecycle` → 403） | 用户在控制台操作 |
| 防盗链 | 待配置 | 同上；且无自有域名时白名单无处可填 | 用户在控制台操作 |
| CDN 接入 | 未开始 | **没有已备案的自有域名**（中国境内加速强制要求） | 用户先办域名 + 备案 |

**不要把桶级权限加给应用密钥。** `.env.example` 里那条约束是对的：应用密钥一旦有
`cos:*`，泄露后对方能把桶改成公有读。桶级配置请用主账号，或单独建一个**只在本地运维脚本里用、
绝不注入容器**的运维子账号。

真正省钱的是「压缩 + CDN」，生命周期和防盗链省的是小钱与风险，别把顺序搞反。

## 1. 现状链路

```
商家/用户上传 ──POST /api/uploads──> 网关 ──> fulfilment ──PUT──> COS uploads/<uuid>.<ext>
                                                                    │
买家浏览    <──GET /uploads/<uuid>.<ext>── 网关 <── fulfilment <───┘   （本地盘兜底时）
买家浏览    <──GET https://<bucket>.cos.ap-guangzhou.myqcloud.com/uploads/<uuid>.<ext>── COS
                                                    ↑ 直连源站：外网下行 0.5 元/GB
```

- URL 契约：`<base>/uploads/<uuid>.<ext>`，`<base>` 由 `UPLOADS_PUBLIC_BASE_URL` 决定，
  留空则按 `X-Forwarded-*` / `Host` 推断。
- 图片是**绝对 URL 落库**的（商品图、评价 `images` JSON、头像、售后举证），
  这意味着**换域名必须做一次数据迁移**，不是改个配置就完事。

## 2. 图片压缩（已落地）

### 2.1 触发时机：读取时实时处理

采用数据万象 `imageMogr2` 的**下载时处理**，不是上传时转码。

| 方案 | 触发点 | 存储 | 可回滚 | 适用 |
|---|---|---|---|---|
| **下载时处理（采用）** | 每次 GET 触发 | 只存原图，容量不变 | 改配置即回滚 | 中小流量、参数需反复调 |
| 上传时持久化 | 上传时处理一次 | 存处理后的图 | 原图已丢，不可逆 | 超大流量、参数已定型 |

讨价还价的依据：**基础图片处理 ≤10TB/月 免费**（按原图大小累计处理量），
超出后 0.025 元/GB。以本项目量级（月处理量预计 60GB 以内）完全落在免费区间。

### 2.2 参数与取值理由

```
?imageMogr2/auto-orient/thumbnail/1600x1600>/format/webp/quality/82/strip
```

| 参数 | 取值 | 理由 |
|---|---|---|
| `auto-orient` | 开 | 按 EXIF 纠正方向。**必须排在 `strip` 之前**，否则手机竖拍图会躺倒 |
| `thumbnail/1600x1600>` | 长边 1600，`>` = 只缩不放 | 主流手机屏宽 390pt × 2 倍图 = 780px，1600 仍有两倍余量；小图不被拉伸 |
| `format/webp` | WebP | 同画质比 JPEG 小 25%~35%，且**支持透明通道**（PNG 转 JPEG 会变黑底） |
| `quality/82` | 82 | WebP 在 q80~85 区间视觉无损；低于 70 才开始出现可察觉块效应 |
| `strip` | 去元信息 | 去掉 EXIF/ICC，通常再省 10~30KB；位置在最后，不影响 auto-orient |

### 2.3 实测数据

同一张商品图 `miniprogram/images/products/p01.jpg`：

```
原图    HTTP 200  image/jpeg  21662 字节
压缩后  HTTP 200  image/webp   6364 字节   -70.6%
```

### 2.4 代码落点

- `duoduo-fulfilment/.../UploadController.java`
  - 新增 `imageSuffix` 配置字段与 `publicUrl(request, stored, ext)`
  - 上传与「远程导入」两条路径共用，返回给前端的 URL 统一带参数
  - **GIF 强制跳过**：`format/webp` 会把动图压成一张静图，表情包会突然不动
- `duoduo-fulfilment/src/main/resources/application.yml` → `duoduo.uploads.image-suffix`
- 环境变量 `UPLOADS_IMAGE_SUFFIX`，**留空即完全关闭**（默认空，行为与改造前一致）

### 2.5 副作用与兜底

- 存量图片 URL 不带参数 → 不受影响，也不会被压糊。需要覆盖存量时单独跑迁移（见 §6.2）。
- 本地盘模式（`STORAGE_TYPE=local`）不要开：没有处理能力，只会让 URL 多一串无效参数。
- WebP 兼容性：iOS 14+ / Android 4.0+ / 全部现代浏览器。若仍担心老设备，
  前端 `<img onError>` 回落到去掉 query 的原 URL 即可（一行代码，未强制接入）。

## 3. CDN 接入

### 3.1 前置条件（当前未满足）

1. **一个已完成 ICP 备案的域名**（中国境内加速强制要求；备案同步有 1~2 小时延迟）。
   没有备案域名只能选「中国境外」加速区域，对国内用户反而更慢，不建议。
2. CDN 服务已开通（控制台点「免费开通」）。
3. 该域名的 HTTPS 证书（腾讯云可申请免费 DV 证书）。

> 买域名 → 实名 → 备案，是整条链上唯一无法由我代劳的环节。备案下来后剩下的配置可以一次做完。

### 3.2 添加加速域名

| 配置项 | 值 |
|---|---|
| 加速域名 | `img.<你的域名>`（例：`img.duoduo.com`） |
| 加速区域 | 中国境内 |
| 加速类型 | CDN 网页小文件（图片平均 < 5MB） |
| 源站类型 | **COS 源** |
| 源站地址 | `duoduo-mall-public-1374887902`（首次需点「添加授权服务」授予 CDN 读桶权限） |
| 回源协议 | HTTPS |
| 私有存储桶访问 | 关闭（该桶是公有读） |

添加后按提示配置 CNAME，用 `nslookup -qt=cname img.duoduo.com` 验证解析生效。

### 3.3 缓存与回源（关键项）

| 配置 | 值 | 说明 |
|---|---|---|
| 节点缓存过期 | `/uploads/` 路径，30 天 | 文件名是 UUID，内容永不变，可长缓存 |
| **忽略参数** | **不忽略**（或仅保留 `imageMogr2`） | ★ 最容易踩的坑：忽略参数会让 `?thumbnail/400` 和 `?thumbnail/1600` 命中同一份缓存，列表页拿到详情页的大图，或反之 |
| 浏览器缓存 | 图片 7 天 | 与 `Cache-Control` 一致 |
| 智能压缩 | 关闭 | 图片已由 imageMogr2 处理，Gzip 对二进制无收益 |
| 分片回源 | 关闭 | 单图 < 5MB |
| HTTPS | 开启并强制跳转 | 小程序要求 HTTPS |
| IP 访问限频 | 单 IP 100 QPS | 防脚本刷流量 |
| 用量封顶 | 日流量 5GB 告警 + 封顶 | 防止被刷爆 |

### 3.4 切换步骤（可回滚）

```bash
# 1) 先只改配置，不动数据，灰度验证
UPLOADS_PUBLIC_BASE_URL=https://img.duoduo.com
# 2) 重启 fulfilment，上传一张图，确认返回的 URL 指向新域名且能打开
# 3) 验证压缩参数在 CDN 链路上也生效
curl -sI "https://img.duoduo.com/uploads/<uuid>.jpg?imageMogr2/auto-orient/thumbnail/1600x1600>/format/webp/quality/82/strip" \
  | grep -i -E "content-type|x-cache|content-length"
# 期望：content-type: image/webp；X-Cache-Lookup: Hit From MemCache（第二次请求）
# 4) 跑数据迁移（§6.2），把存量绝对 URL 换成新域名
# 5) 小程序后台把 downloadFile 合法域名加上 img.duoduo.com
```

回滚：`UPLOADS_PUBLIC_BASE_URL` 改回桶域名并重启；数据迁移用反向 UPDATE 撤回。

## 4. 存储生命周期规则

### 4.1 先说不能做什么

`uploads/` 下**混着商品图、评价晒单图、售后举证图、用户头像**，它们全是 UUID 命名、
没有业务前缀。**对这个前缀设「N 天后删除」等于到期自动删光全站图片**，且不可逆。
任何方案里出现「uploads/ 全量过期删除」都是错的。

因此规则只能落在两个**安全的**位置上：

### 4.2 规则表

| # | 适用范围 | 触发条件 | 到期处理 | 风险 |
|---|---|---|---|---|
| **A** | 整个桶（含两个桶） | 分片上传超过 **3 天**仍未完成 | 中止并删除碎片 | 无。碎片本来就不会被读到，只占容量 |
| **B** | 前缀 `uploads/tmp/` | 对象创建满 **7 天** | 删除 | 低。需先建立该分区（§4.3） |
| C | 前缀 `uploads/` | 创建满 N 天 | 删除 | **禁止**，见 §4.1 |
| D | 前缀 `uploads/` | 90 天未访问 | 转低频存储 | 中。商品图会被反复访问，低频有最短存储期与取回费，可能更贵 |

### 4.3 规则 B 的前置：建立临时分区

现在 `UploadController` 固定写 `uploads/<uuid>.<ext>`，测试图与业务图无法区分。
要让规则 B 生效，需要给上传端点加一个可选的 `scope=tmp` 参数，
落到 `uploads/tmp/` 前缀，并同步放开 `GET /uploads/` 的子目录读取。

**当前评估：这条的收益极小**（测试图总量在百 MB 级，存储费按 0.118 元/GB·月 计不足 0.1 元/月），
优先级排在 CDN 之后。先做规则 A 就够了。

### 4.4 配置路径

COS 控制台 → 选中桶 → 基础配置 → 生命周期 → 添加规则：
- 规则 A：`适用范围=整个存储桶`，`删除碎片文件=开启`，`碎片保留 3 天`
- 规则 B：`适用范围=指定前缀`，`前缀=uploads/tmp/`，`对象创建后 7 天删除`

> 需要桶级 `PutBucketLifecycle` 权限。当前应用 AK 没有（`GET ?lifecycle` 返回 403），
> 这是当初按最小权限刻意设计的，不要为了配规则给它加权限。

## 5. 防盗链

### 5.1 必须先想清楚一件事

微信小程序的图片请求带 `Referer: https://servicewechat.com/<appid>/<version>/page-frame.html`，
而**直接打开图片链接、部分客户端、curl 都不带 Referer**。

所以：

- 若不允许空 Referer → **小程序图片全裂**、用户复制链接打不开
- 若允许空 Referer → 防盗链只能挡住「带错误 Referer 的网页盗链」，挡不住脚本直连

结论：**防盗链是「降低被普通站点盗链的概率」，不是「防刷」。防刷靠 CDN 的用量封顶 + IP 限频。**

### 5.2 配置

走 CDN 后在 **CDN 控制台 → 访问控制 → 防盗链** 配置（不要配在 COS 桶上，
否则 CDN 回源会被自己的防盗链挡住，现象是全网 403）：

| 项 | 值 |
|---|---|
| 类型 | Referer 黑白名单 → **白名单** |
| 允许的 Referer | `*.duoduo.com`（自家站点）<br>`servicewechat.com`（小程序）<br>`*.servicewechat.com` |
| 空 Referer | **允许**（不可关闭，见 §5.1） |
| 非法请求处理 | 返回 **403**，**不回源**（省回源流量与图片处理费） |
| 有效期 | 不需要 |

### 5.3 更强的方案（暂不采用）

COS 支持 URL 签名（`q-sign`）把链接变成有时效的私有地址，但：

- 每个用户拿到的 URL 不同 → CDN 缓存命中率归零，回源量暴涨
- URL 会过期 → 数据库里的绝对 URL 全部失效，需要改成「存储 key + 实时签名」
- 与现有「UUID 不可枚举」的安全模型重复

现阶段用 Referer 白名单 + UUID 文件名 + 用量封顶即可，上量后再评估签名 URL。

## 6. 成本影响

### 6.1 单位成本对比

| 项 | 单价 | 备注 |
|---|---|---|
| COS 外网下行（现状） | **0.5 元/GB** | 直连源站，全额计费 |
| CDN 中国境内流量 | **0.21 元/GB**（0~2TB 阶梯） | 2~10TB 0.20 |
| COS → CDN 回源流量 | **0.15 元/GB** | 只在缓存未命中时产生 |
| 请求次数 | 0.01 元/万次 | 读写同价 |
| CDN HTTPS 请求 | 约 0.05 元/万次量级 | 以控制台报价为准 |
| 基础图片处理 | **≤10TB/月 免费** | 超出 0.025 元/GB |

即使 CDN 缓存命中率为 0（0.21 + 0.15 = 0.36 元/GB），仍低于直连的 0.5 元/GB。
命中率越高越省。

### 6.2 三种状态的月度成本（假设月图片下行 100GB、50 万次请求）

| 状态 | 计算 | 合计 |
|---|---|---|
| 现状（直连） | 100×0.5 + 0.5 | **50.5 元** |
| 仅压缩（-70%） | 30×0.5 + 0.5 | **15.5 元** |
| 压缩 + CDN（命中率 85%） | 30×0.21 + 4.5×0.15 + 0.5 + 2.5 | **约 9.7 元** |

**仅压缩这一项就能砍掉约 70% 的流量费，且当天生效、零新增产品依赖。**

### 6.3 数据迁移（换域名时必须做）

存量 URL 是绝对地址，换 CDN 域名后需要更新。涉及字段（执行前先核对）：

| 表 / 字段 | 内容 |
|---|---|
| `t_product.image` | 商品主图 |
| `t_product_image.url` | 商品图集（若有独立表） |
| `t_review.images` | 评价图，JSON 数组 |
| `t_user.avatar` | 用户头像 |
| 售后举证图字段 | JSON 数组 |

迁移脚本只做**前缀替换**，且限定为自家桶域名：

```sql
-- 先统计影响面（务必先跑这个）
SELECT COUNT(*) FROM t_user
 WHERE avatar LIKE 'https://duoduo-mall-public-1374887902.cos.ap-guangzhou.myqcloud.com/%';

-- 确认后再更新（示例，逐表执行）
UPDATE t_user
   SET avatar = REPLACE(avatar,
       'https://duoduo-mall-public-1374887902.cos.ap-guangzhou.myqcloud.com',
       'https://img.duoduo.com')
 WHERE avatar LIKE 'https://duoduo-mall-public-1374887902.cos.ap-guangzhou.myqcloud.com/%';
```

**只替换自家桶域名，不要动外链**（用户填过外部图床的评价图，替换后会全裂）。

## 7. 对现有访问流程的影响

| 环节 | 影响 | 处理 |
|---|---|---|
| 上传 | 返回值多一段 query | 前端原样存库即可，无需解析 |
| 展示 | `<img src>` / `<image src>` 带 query | 浏览器与小程序都正常，无需改组件 |
| 存量图 | 不带参数，不压缩 | 可接受；需要时跑迁移 |
| 本地盘模式 | query 被 Spring 忽略 | 行为不变 |
| 小程序域名白名单 | 换 CDN 后需加 downloadFile 域名 | 微信公众平台后台操作 |
| 后台/商家端 | 共用同一个 base | 一起生效，无需分别配 |
| CDN 缓存 | 参数必须参与缓存键 | 见 §3.3，否则尺寸串味 |
| 防盗链 | 空 Referer 必须放行 | 否则小程序裂图 |
