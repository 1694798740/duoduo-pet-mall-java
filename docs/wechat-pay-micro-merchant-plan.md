# A3 · 微信支付接入方案（小微 / 无营业执照主体的可行路径）

> 日期：2026-10-20　｜　背景：你是小微经营者，**没有营业执照**，因此申请不到商户号、
> API v3 密钥与商户证书。本文回答两件事：① 在此限制下有哪些路可走；② 推荐哪条、怎么落地。

---

## 一、先说结论

**卡点不在代码，在「小程序主体类型」。**

代码这边其实已经万事俱备（`duoduo-trade` 已有完整的微信支付渠道实现），
真正拦路的是两条微信官方硬规则：

1. **个人主体小程序禁止绑定支付商户号**（微信官方明确答复）；
2. **小程序主体类型一经选定不可更改**。

所以——**必须先解决主体问题，才有资格谈接入**。推荐路径是：

> **办一张个体工商户营业执照 → 重新注册「个体工商户」主体的小程序 → 申请商户号 → 填配置（代码不用改）。**

---

## 二、代码侧现状：已经写好了，只差凭据

`duoduo-trade/src/main/java/com/duoduo/trade/payment/` 下已有完整实现：

| 文件 | 作用 |
| --- | --- |
| `wechat/WechatJsapiPayChannel.java` | **小程序 / 公众号支付（JSAPI）** —— 本项目要走的就是这条 |
| `wechat/WechatNativePayChannel.java` | 扫码支付（Native） |
| `wechat/WechatH5PayChannel.java` | H5 支付 |
| `wechat/WechatPayConfig.java` | 读 `duoduo.pay.wechat.*` 配置 |
| `wechat/WechatPayCrypto.java` | 签名 / 验签 / 敏感信息加密 |
| `SandboxPaymentChannel.java` | **当前在用的仿真渠道**（收银台页面 `/sandbox/pay/{payNo}`） |

`docker-compose.yml` 里 8 个环境变量已经预留好，只等你填：

```
WECHAT_PAY_ENABLED          # false → true 即切换到真实渠道
WECHAT_PAY_APPID            # 小程序 AppID
WECHAT_PAY_MCHID            # 商户号
WECHAT_PAY_API_V3_KEY       # API v3 密钥
WECHAT_PAY_PRIVATE_KEY_PEM  # 商户 API 证书私钥
WECHAT_PAY_MERCHANT_SERIAL_NO  # 商户 API 证书序列号
WECHAT_PAY_PLATFORM_CERT_PEM   # 微信支付平台证书
WECHAT_PAY_NOTIFY_URL       # 公网 https 回调地址
```

**结论：拿到资质后不需要开发，填完 8 个变量 + 重启 trade 容器即可切换。**

## 三、三条路径对比

| | ① 个体工商户（**推荐**） | ② 小微商户进件 | ③ 个人升级版小程序 |
| --- | --- | --- | --- |
| 是否需要执照 | **需要**（办一张） | 不需要 | 不需要 |
| 谁去申请 | 你自己 | **必须通过服务商 / 银行**（个人无法自助申请） | 必须由**第三方平台服务商**代开发并代缴保证金 |
| 小程序主体 | 个体工商户（需重新注册） | 个人主体**仍绑不了商户号** | 个人主体（服务商代开发） |
| 小程序支付 | ✅ 完整支持 | ✅ 支持（但见限制） | ✅ 支持 |
| 收款限额 | 同普通商户，无歧视 | 单笔 500~1000 元起；信用卡月限 1 万、日限 1000；日收款 5~30 万 | 由服务商保证金与类目决定 |
| 费率 | 按行业，多为 0.6% | 0.38%~0.6%（十一档） | 同服务商约定 |
| 结算账户 | 个体户可用**经营者私人账户**（不必对公） | 个人银行卡 | 个人银行卡 |
| 适用行业 | 全类目 | 偏线下（餐饮/零售/生活服务等） | 有限类目 |
| 成本 | 执照免费 + 微信认证 30~300 元/年 | 服务商通常收通道费 | 需服务商配合，个人难以自行推进 |

**为什么不选 ②**：小微商户虽支持小程序支付，但必须由服务商进件、限额严苛，
且**个人主体小程序依然禁止绑定商户号**——这条路对你的场景走不通。

**为什么不选 ③**：要求服务商考核「优秀 / 良好」并为你缴纳交易保证金，
且小程序须由服务商代开发。我们是自研自管，不适用。

**不推荐的旁门**：用个人收款码收线上订单。远程收款会被微信风控，
且没有自动回调、无法对账、订单状态无法自动流转 —— 对电商系统是致命的。

## 四、推荐方案落地步骤（按顺序做）

### 第 0 步：先确认一件事（决定后面要不要重注册）

微信公众平台 → 设置 → 基本设置 → **主体信息**，看主体类型。

- 若是「个人」→ 下面的第 2 步**必须**做（重新注册小程序，AppID 会变）；
- 若已经是「个体工商户 / 企业」→ 直接跳到第 3 步。

### 第 1 步：办个体工商户营业执照

- 途径：当地市场监管局 App / 政务服务网，多数地区支持**全程网上办、免登记费**；
- 材料：身份证、经营场所证明（多数地区允许住宅登记或集群注册）、名称、经营范围
  （建议含「互联网销售」「宠物用品零售」「日用百货销售」）；
- 出证：多数地区当天到几个工作日。

### 第 2 步：注册「个体工商户」主体的小程序（个人主体时才需要）

- 主体类型**不能改**，只能新注册 → 会拿到**新的 AppID**；
- 影响：小程序的 `AppID` 变了，我们的 `.env`（`WECHAT_APPID`）、
  以及已申请的地理位置接口权限都要在新主体上**重新申请一遍**；
- 旧的小程序可以留作体验版，或停用。

### 第 3 步：微信认证

- 费用：个体工商户通常 30 元（简化认证）或 300 元/年（标准认证），以页面提示为准；
- 认证后才有完整接口权限（支付、订阅消息等）。

### 第 4 步：申请商户号

- 入口：微信支付商户平台（pay.weixin.qq.com）→ 成为商户 → 主体类型选「个体工商户」；
- 材料：营业执照、经营者身份证、结算银行账户（**个体户可用经营者私人账户**）；
- 账户验证：法人微信扫码，或汇款验证。

### 第 5 步：开通产品 + 拿密钥证书

1. 商户平台 → 产品中心 → 开通 **JSAPI 支付**（小程序支付就是它）；
2. 账户中心 → API 安全 → 设置 **API v3 密钥**；
3. 账户中心 → API 安全 → 申请 **API 证书**（下载私钥 `apiclient_key.pem` + 证书序列号）；
4. 下载**微信支付平台证书**（用于验签回调）。

### 第 6 步：绑定 AppID

- 商户平台 → 产品中心 → AppID 授权管理 → 添加你的小程序 AppID；
- 再回小程序后台确认授权。**两边主体必须一致**，否则绑不上。

### 第 7 步：填配置并切换

- 把第 5 步的凭据填进 `.env` 的 8 个变量（见第二节表格）；
- `WECHAT_PAY_ENABLED=true`；
- **重建 trade 容器**（环境变量不热更新）；
- `WECHAT_PAY_NOTIFY_URL` 必须是**公网 https**——本机开发期用内网穿透域名，
  正式上线后换成真实域名。

### 第 8 步：验证

1. 用 1 分钱下真实订单，确认能拉起支付、能支付成功；
2. 确认回调能打到、订单自动流转到「已支付」；
3. 走一笔退款，确认退款回调与订单状态一致；
4. 对账：商户平台账单与本系统 `t_payment` 逐笔核对。

## 五、前置要求与风险清单

| 项 | 说明 |
| --- | --- |
| **主体一致性** | 小程序主体、商户号主体、结算账户户名三者要能对上，否则绑不上或结算失败 |
| **AppID 变更** | 若需重注册小程序，AppID 变化会连带影响已申请的接口权限、已配置的 `.env`、小程序端配置 |
| **回调地址** | 必须是公网 https。当前只在本机跑，需要内网穿透或正式部署环境 |
| **切换期** | 建议保留沙箱渠道开关，真实渠道异常时可一键回退（代码已支持 `WECHAT_PAY_ENABLED` 开关） |
| **资金安全** | 商户证书私钥只放 `.env`（已在 `.gitignore` 中），不进仓库、不进前端产物 |
| **未拿资质前** | 保持现状（沙箱仿真渠道），功能验收不受影响，只是不能真收款 |

## 六、建议的推进顺序

1. **现在**：让 A3 处于「等资质」状态，不阻塞其他工作；
2. **并行**：先推进不依赖资质的 A2（暗夜模式，四端）；
3. **资质办下来后**：按第四节第 4~8 步执行，届时**只需配置、无需开发**。
